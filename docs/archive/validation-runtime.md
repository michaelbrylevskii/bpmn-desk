## Что проверено

- Секрет сессии не записывается в `connections.json`, после перезапуска требуется повторный ввод. Профили и последнее выбранное подключение сохраняются; проверено восстановление профиля, который находится вторым в списке. Контракт запоминания проверен с тестовым адаптером хранилища; недоступное хранилище запрещает постоянное сохранение. Реальная разблокировка системного keyring в этой среде не подтверждена.
- Чтение API выполняется GET, дочитываются страницы executions. Ошибка доступа к jobs сохраняет остальные разделы снимка и показывает предупреждение.
- Экземпляр первой версии открывает именно v1 при наличии опубликованной v2. Локальная копия открывается в редакторе; исходный просмотрщик не содержит палитру моделирования.
- На параллельной схеме активны задача владельца и три multi-instance задачи. Счётчик не включает родительский execution-контейнер. Локальная переменная execution читается отдельно.
- Примитивные и вложенные JSON-переменные читаются и раскрываются в UI. Бинарные/Java-serialized значения не десериализуются редактором.
- Настоящий async executor выполняет падающий delegate, исчерпывает retry и создаёт dead-letter с сообщением и stacktrace. В UI доступны список, переход к экземпляру, красная подсветка, подробности и переменные. Повторный выбор задания возвращает секцию jobs.
- Ручное и периодическое обновление не пересоздают холст и не меняют viewport. Переключение редактор/монитор сохраняет локальные правки и undo, а также положение runtime-схемы.
- Проверены ошибка авторизации, выбор разных профилей, восстановление списка после перезапуска, русская локаль и тёмная тема.
- Несколько мониторов одного подключения сохраняют независимые экземпляры, фильтры и холсты. Закрытие возвращает соседнюю вкладку; отмена закрытия изменённого документа сохраняет его, включая черновик XML и undo.
- Проверка формы до сохранения работает с пустым названием, использует введённый пароль и не создаёт профиль. Проверка изменённого сохранённого профиля не меняет секрет. После сохранения неверного и затем правильного пароля каталог перечитывается, открытый экземпляр и DOM холста сохраняются.
- В строках экземпляров показывается имя определения из ответа REST. Проверены ключ процесса, размер страницы и направление сортировки; отдельная REST-проверка сверяет paginated ответ и metadata.
- Длинный business key не создаёт горизонтальный скролл каталога и правой панели при 1050×680 в обеих темах. Выбранные строки имеют акцентное выделение. Нативных HTML select в UI нет.
- Listbox проверены мышью и клавиатурой, в длинных формах Camunda и в модальном редакторе подключения. Escape сначала закрывает список, затем окно; обновление native меню языка не закрывает popup преждевременно.
- Клик на элемент выделяет его на холсте и показывает тот же ID в правой панели. Фокус SVG использует акцент приложения в обеих темах. Цифры бейджей центрируются через flex; точка — отдельный круг.
- Runtime SVG содержит маркеры и счётчики, не содержит CSS variables и selection outlines. PNG с белым фоном проверен по сигнатуре, пикселям фона и наличию зелёных меток. Экспорт не меняет BPMN, dirty state и recent files; unit-проверка покрывает текущую плоскость и границы длинных бейджей.
- Скриншоты редактора пересозданы из встроенного оригинального примера в двух темах и локалях. Пользовательские схемы и данные сервера в документацию не копировались.
- Вызванный процесс открывает своё определение; доступны переходы от ребёнка к родителю и обратно, с подсветкой call activity.
- Native меню по умолчанию скрыто, auto-hide включён; действующие native сочетания клавиш остаются рабочими. Нажатие Alt для системного меню реализуется Electron; реальное событие клавиатуры ОС требует ручной проверки.

## Границы проверки

Новые runtime-сценарии проверены локально на Linux. В workflow добавлены независимые runtime-прогоны для Linux и Windows, но эта ветка не отправлялась и её CI не запускался. Новые Windows/macOS проверки не заявляются. Доступ к конкретному пользовательскому серверу, корпоративной авторизации и сертификатам не подтверждён.

Административные операции, исторические экземпляры, обычные/timer jobs и runtime Camunda 7 не входят в этот этап. Ограничения сети, полноты снимка и переменных описаны в [runtime-monitor.md](../runtime-monitor.md). Предыдущий релиз и его отчёт [validation-0.3.0.md](validation-0.3.0.md) сохранены.

## Доступ к файлам из любой вкладки — 2026-10-10

После расширения диалога «Новая вкладка» прошли `npm run check` (71 unit-тест), `npm run test:e2e` (62 проверки) и повторный полный `npm run test:runtime` (11 проверок). AppImage пересобрана и запущена в E2E; renderer внутри ASAR совпадает с текущим `out`.

Проверены открытие примера из редактора и монитора, сохранение контекста монитора и undo документа, появление только что сохранённого файла в недавних без изменения числа вкладок, активация уже открытого файла с сохранением черновика и ошибка при удалённом файле. Диалог помещается в окно 1050×680 в обеих темах, заголовок и закрытие доступны при прокрутке. Перетаскивание файла в диалог закрывает его и открывает документ.

В первом runtime-прогоне один сценарий остановился при начальном выборе подключения: popup `@new` исчез до клика E2E. Повторный полный прогон прошёл 11/11. Причина однократного сбоя не установлена.

## Ревью UX и ограниченная сводка — 2026-10-10

Изменения: `e004159` — переход из сообщения о dead-letter и пустые разделы; `d4eb191` — ограниченная сводка, latest и явная недоступность данных; `402f186` — переходы из сводки к экземплярам; `a2dd5b0` — регистрация hooks runtime-стенда в каждом spec. Ветка остаётся локальной, версия 0.3.0; новые теги и релизы не создавались.

Финальные результаты на Linux: `npm run check` — 78 unit-тестов в 22 файлах, strict TypeScript и ESLint; `npm run test:runtime` — 13/13 на независимом Flowable 7.2/H2; `npm run test:e2e` — 62/62 (51 Chromium, 10 Electron, 1 AppImage), Windows и 13 runtime-тестов без стенда корректно пропущены. `npm run package:linux` собрала AppImage, проверенную общим E2E с включённым sandbox. Семь файлов main/preload/renderer внутри ASAR совпадают с текущим `out`; тестов, стенда, документации, кешей и настроек подключений в архиве нет. Новые Windows/macOS прогоны не выполнялись.

Проверены:

- Сообщение о dead-letter открывает ошибки и передаёт фокус кнопке раздела; переход к месту ошибки выделяет элемент. Пустые tasks/executions не выглядят незагруженной панелью, scope без позиции не изображает ссылку.
- Сводка выполняет ровно два GET выбранной версии, не обходит страницы и не запрашивает каждый экземпляр. Multi-instance одного экземпляра считается один раз; красный счётчик обозначает разные экземпляры с dead-letter.
- Миллионный `total` в независимом HTTP-ответе ограничен 100 записями; метка `≥ N` и предупреждение явно показывают неполноту. Отказ доступа к jobs не превращается в ноль. Отдельные unit-сценарии проверяют зависание до headers и во время body, общий deadline и отказ от серверной страницы сверх лимита.
- При медленном ответе можно перейти к другой версии; поздний результат не применяется, повторное чтение сводки остаётся недоступным до завершения предыдущего. Отсутствуют фоновые повторы и дополнительные запросы при локальной пагинации списка связанных экземпляров.
- Из элемента сводки можно открыть экземпляр, а из строки с ошибкой — сразу его раздел jobs. Старый экземпляр открывает v1 при включённом фильтре latest; `latest=true` проверен с ключом и поиском по имени на настоящем API.
- Недоступные переменные/tasks/jobs отображаются как недоступные, а не пустые; неизвестный счётчик jobs показан как `—`. Поиск по переменным явно сообщает отсутствие совпадений. Состояние списка экземпляров компактно обозначает приостановку и не объявляет процесс выполняющимся прямо сейчас.
- Скриншоты сводки проверены в обеих темах при 1050×680. После изменения размеров окна схема и бейдж действительно находятся внутри холста. Сводка экспортируется в SVG; общие runtime-проверки SVG/PNG и сохранения viewport проходят.

Первый общий E2E после добавления сводки завершился с 62 успешными проверками и одной ошибкой тестовой обвязки: адрес fixture читался до пропуска runtime-сценария без стенда. Hooks общего helper регистрировались при его импорте и зависели от кеширования модуля. Исправлена явная регистрация в каждом spec и убрано раннее чтение fixture из параметра по умолчанию. После исправления отдельно проверены 13 пропусков без стенда, полный runtime-прогон 13/13 и повторный общий E2E 62/62.

Решения и ограничения описаны в [ADR 0022](../adr/0022-bounded-definition-summary.md). Глобальные фильтры определений «с экземплярами»/«с ошибками» не вводились: фильтрация текущей страницы не дала бы корректный общий список.

## Удаление индикаторов из списка экземпляров — 2026-10-10

После UX-проверки статусные точки и подписи Active/Suspended исключены из списка экземпляров. Состояние приостановки и сведения о dead-letter отображаются в правой панели. Цвета строк не меняются по мере выборочного открытия экземпляров; дополнительных запросов к jobs не добавлено. README, руководство и ADR приведены к этому решению.

Прошли `npm run check` (78 unit-тестов), `npm run test:runtime` (13/13), `npm run package:linux` и `npm run test:e2e` (62/62, включая свежую AppImage; Windows и runtime без стенда пропущены). Регрессионный сценарий проверяет активный экземпляр с одной dead-letter job: в строке нет статусного изображения и Active, а правая панель показывает Active и сообщение о задании с ошибкой. Отдельно проверено отсутствие маркера у экземпляра без dead-letter. Новые Windows/macOS проверки не выполнялись.

## Общая стартовая страница и переключатель языка — 2026-10-10

Изменения: `86b6515` — цельная кнопка языка; `68c4996` — общая стартовая страница и обычные пустые вкладки.

Главная страница и обычная вкладка «Новая вкладка» используют один `Welcome` и общий набор действий `WorkspaceLauncher`. Проверены создание BPMN 2.0 / Flowable / Camunda 7, клавиатурное меню создания, открытие монитора с главной, примеры, recent, drop и native выбор файла. Успешное открытие заменяет исходную стартовую вкладку, отмена и ошибка оставляют её. Уже открытый файл активируется без перезагрузки черновика. Отдельные unit-сценарии проверяют порядок вкладок, поздний ответ после закрытия исходной вкладки и сохранение соседнего монитора.

Ctrl+N завершает ввод в активном поле; возврат сохраняет модель и undo. Соседние редакторы и мониторы остаются смонтированными. Скриншоты стартовой страницы просмотрены в обеих темах при 1050×680; колонки допускают сжатие при длинных названиях. Переключатель языка проверен кликом непосредственно по глобусу и клавиатурой: это одна кнопка с одной рамкой фокуса.

Результаты на Linux: `npm run check` — strict TypeScript, ESLint и 83 unit-теста в 23 файлах; `npm run test:e2e` — 65 успешных проверок (53 Chromium, 11 Electron, 1 AppImage), 14 пропусков (Windows и runtime без стенда); `npm run test:runtime` — 13/13 на независимом Flowable 7.2/H2. `npm run package:linux` собрала актуальную AppImage, запущенную общим E2E с sandbox. Семь файлов main/preload/renderer внутри ASAR совпадают с `out`. Новые Windows/macOS проверки не выполнялись, пуша, тегов и релизов нет.

Первый общий прогон остановился на двух проверках Electron: точное имя кнопки включало подсказку Ctrl+O, а сценарий ошибки recent ожидал прежний документ вместо сохранённой стартовой страницы. Исправлены доступное имя кнопки и ожидание теста; черновик проверяется после возврата к документу. Подтверждение закрытия в новом тесте подменяется до начала сценария, чтобы таймаут не оставлял native диалог несохранённых изменений. После исправлений полный общий прогон прошёл без зависших окон.

Решение зафиксировано в [ADR 0023](../adr/0023-start-page-tabs.md), устройство переключателя языка — в [ADR 0008](../adr/0008-languages-and-compact-search.md).

Браузерное preview показывает недоступную кнопку управления; runtime-тулбар не дублирует общую кнопку.

Прошли `npm run check` (83 unit-теста, strict TypeScript и ESLint), `npm run test:runtime` (13/13 на Flowable 7.2/H2), `npm run package:linux` и `npm run test:e2e` (65 успешных проверок, включая свежую AppImage с sandbox; 14 пропусков — Windows и runtime без стенда). Семь файлов main/preload/renderer в ASAR совпадают с текущим `out`. Проверки выполнены на Linux; новые Windows/macOS прогоны не заявляются. Ветка остаётся локальной, без пуша, тегов и релизов.
