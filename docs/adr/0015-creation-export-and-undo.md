# 0015. Создание схем, экспорт изображений и точный undo

Статус: принято. Дата: 2026-10-09. Уточняет ADR 0007, 0010 и 0014.

## Контекст

Селектор профиля рядом с кнопкой создания легко пропустить: новая схема выглядит как неявный выбор Flowable. Имена части примеров не показывают движок. Постоянный Offline badge дублирует документацию. Поиск XML должен открываться и закрываться одной кнопкой; экспорт нужен также в PNG.

Обнаружена причина ложного dirty state: BpmnUpdater создаёт пустой BPMNLabel при изменении названия и при revert оставляет его даже там, где исходная DI не имела этого узла. Простое выключение индикатора по пустому command stack скрыло бы это изменение XML.

## Решение

- Все способы создания — welcome, toolbar, новая вкладка, Ctrl+N и native меню — используют один диалог выбора BPMN 2.0 / Flowable / Camunda 7. Escape отменяет создание. Открытые схемы сохраняют автоматическое определение по URI. Постоянный селектор и Offline badge удалены.
- Все встроенные примеры получают префикс `flowable-` или `camunda7-`. Исходный XML заимствованных схем остаётся побайтово прежним: меняются только имена и соответствующие записи provenance. Исторические ADR/отчёты сохраняют прежние названия.
- Цвет точки рядом с названием профиля показывает движок, не результат проверки: зелёный Flowable, оранжевый Camunda 7.
- Состояние кнопки XML-поиска берётся из CodeMirror. Кнопка переключает панель, Ctrl+F открывает/фокусирует её, Escape закрывает; запрос остаётся в состоянии редактора.
- `bpmn/label-presence` запоминает исходную DI label, её bounds и наличие координат до updateLabel/move/resize. После штатного revert и завершающего shape.changed возвращает эти DI-данные перед публикацией XML. Это также покрывает различие исходных DI bounds и импортированной визуальной геометрии. Стиль и ссылки существующей подписи сохраняются. Dirty state продолжает сравнивать фактический XML, без маскировки отличий.
- Экспорт — split button: основной клик повторяет выбранный вариант; меню выбирает и сразу экспортирует SVG, PNG с белым фоном или PNG с прозрачностью. Выбор действует в текущей сессии.
- PNG создаётся из самодостаточного SVG через встроенные Image/canvas API Chromium, в `renderer/bpmn/image-export`, без новой зависимости. Схема использует светлую экспортную палитру; явные DI-цвета сохраняются. UI/сетка/панели не попадают в изображение.
- PNG имеет размеры 2× SVG, с округлением вверх. Пределы: сторона до 16 384 px, площадь до 32 млн пикселей; превышение показывает предложение использовать SVG. Масштаб не уменьшается скрытно.
- IPC явно различает текстовый BPMN/SVG и бинарный PNG Uint8Array. Main проверяет тип, PNG signature и размер; экспорт всегда требует отдельный save dialog и не использует capability BPMN. Запись атомарная, recent files и сохранённое состояние документа не меняются.

## Альтернативы и последствия

Снимок DOM/окна включал бы тему UI и зависел от текущего viewport. Отдельная raster-библиотека добавила бы runtime-зависимость без необходимости: Chromium уже умеет растрировать SVG. Белый фон выбран для непрозрачного PNG, чтобы соответствовать светлой экспортной палитре.

Отключение dirty по отсутствию undo-команд отвергнуто: чистое состояние определяется реальными данными. Остаётся ограничение полного PNG размером 20 МБ на запись, как у других сохранений. SVG подходит для схем большего размера. Код PNG проверен на Linux; новую функциональность Windows/macOS нельзя считать проверенной без запуска на этих ОС.

Регрессии проверяют pixel alpha/фон PNG, сохранность XML и dirty при экспорте, native бинарную запись/отклонение неверного payload, все способы создания, prefix/provenance, toggle XML-поиска и undo/redo названий с существующей и отсутствующей DI-подписью.
