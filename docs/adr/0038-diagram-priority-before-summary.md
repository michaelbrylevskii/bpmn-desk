# 0038 — Отображение схемы раньше сводки

Статус: принято. Дата: 2026-10-30. Уточняет порядок загрузки из [ADR 0037](0037-global-summary-and-history.md) по обратной связи после ручной проверки.

## Причина

Независимые запросы сводки не блокировали импорт SVG в приложении, но могли конкурировать с чтением определения/XML на самом движке. Для пользователя получение схемы важнее статистики.

## Решение

Сначала читается точная версия определения и XML, затем завершается импорт в bpmn-js. После отрисовки (два requestAnimationFrame, без фиксированной задержки) схема сообщает о готовности. Только после этого разрешены первые и последующие запросы сводки. Авторефреш уже отображённой схемы не требует повторного импорта. Бюджет подключения начинается с фактического чтения сводки; ожидание схемы в него не входит.

Сигнал принадлежит конкретному объекту загруженной схемы, соединению и ревизии профиля. Готовность предыдущей схемы не разрешает статистику новой. Смена определения, конфигурации или скрытие монитора не применяет поздние ответы. Пока схема не показана, ручное обновление сводки недоступно; иконка сообщает об ожидании отображения.

Если вместо холста открыт XML (нет BPMN DI либо импорт не удался), его отображение также разрешает сводку. Отказ получения определения/XML не запускает запросы статистики. Уже отправленный запрос прежней сводки сохраняет прежний deadline и очередь; отмена серверного SQL этим решением не добавляется.

## Проверка

Electron-стенд удерживает ответ XML: до его освобождения запросов сводки нет. Проверяются первая схема, переход с уже готовой схемы на другую, отказ загрузки и отсутствие BPMN DI с XML fallback. Сохранены проверки медленной сводки, скрытого монитора, очереди, лимитов 100/100/1000 и состояния холста. Новых зависимостей и IPC-контрактов нет.
