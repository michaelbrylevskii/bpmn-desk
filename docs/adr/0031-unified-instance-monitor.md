# 0031. Общая схема runtime и истории

## Контекст

Два режима просмотра одного экземпляра создавали лишнее переключение схемы и разную ширину панели. Во время выполнения полезно одновременно видеть пройденный маршрут, повторы и текущие позиции. При этом history без endTime не подтверждает активность.

## Решение

- Одна схема точной версии процесса и два независимых источника снимков. Выбор вкладки справа меняет только подробности. Масштаб, выбранный элемент, обновление и экспорт схемы от вкладки не зависят.
- Один маркер и один бейдж на BPMN ID. Приоритет: dead-letter, runtime, history. Зелёный цвет устанавливается только по runtime-позициям. Исторические записи без окончания, не подтверждённые runtime, остаются оранжевыми.
- На повторно посещённом текущем узле отдельно показываются зафиксированные окончания (`✓`), текущие executions (`●`) или dead-letter jobs (`!`). Неполная история сохраняет нижнюю границу `≥`. Стрелки берутся только из записанных sequenceFlow.
- Main возвращает `null` для снимка runtime только после HTTP 404 метаданных экземпляра; другие ошибки сохраняют семантику отказа. Подтверждённое отсутствие удаляет прежние runtime-позиции. Ошибка обновления сохраняет старый снимок с предупреждением и временем чтения. Отсутствие в runtime само по себе не доказывает успешного завершения.
- Оба источника работают и при недоступности другого, имеют собственные ошибки и время. Ручное обновление читает оба. Автообновление приостановлено в неактивных мониторах и скрытом окне; history прекращает опрос после endTime, runtime — после 404. Переключение вкладок справа не запускает дополнительные чтения.
- Связи используют одинаковую карточку для родителя и дочернего экземпляра: роль, схема, business key/имя и ID. ID нужен для различения нескольких запусков одной схемы. При отсутствии имени показывается ключ определения; недоступные метаданные не скрывают ссылку.

## Последствия

Открытие текущего экземпляра дополнительно читает ограниченный снимок истории по правилам ADR 0030. Снимки не транзакционны и могут отражать разные моменты; интерфейс не делает из их сочетания вывод об успехе или строгом порядке. Ошибка одного API не лишает пользователя доступного источника. Базовые ограничения истории, приватности, чтения через IPC и неизменности BPMN сохраняются.
