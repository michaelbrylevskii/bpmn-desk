# 0040 — Размещение бейджей на плотных схемах

Статус: принято. Дата: 2026-10-30. Дополняет ADR 0039.

## Причина

Бейджи, привязанные к одному нижнему правому углу каждого элемента, перекрываются у соседних граничных событий. Длинные секции истории и runtime делают наложение заметнее и мешают определить принадлежность счётчика.

## Решение

Перед отображением вычислять позиции всех меток в координатах BPMN. Сначала размещать небольшие события, затем крупные элементы; при равных размерах использовать координаты и ID. Порядок записей API на результат не влияет. Для каждого бейджа искать ближайшее свободное место вокруг элемента с зазором 6 единиц, учитывая полную ширину секций, соседние бейджи, фигуры и внешние подписи текущей плоскости. Контейнеры-предки не блокируют размещение внутри них. В полностью занятом окружении метку выносить ниже препятствий.

Тонкая линия связывает бейдж с границей его элемента. При локальном поиске исключаются места, где линия пересекла бы чужую метку или фигуру, а новый бейдж закрыл бы уже размещённую линию привязки. XML, BPMN DI, модель и command stack не изменяются. При изменении значений раскладка пересчитывается; неизменившийся HTML сохраняется и только перемещается при необходимости. Масштаб и ручное положение viewport при обновлении данных не сбрасываются. Команда вписывания схемы учитывает вынесенные метки.

Позиции и линии одинаковы для HTML и автономного SVG/PNG. Жесты колёсика продолжают проходить к холсту. Алгоритм избегает прямоугольников фигур, подписей и других меток, но не перестраивает маршруты sequence flow и не маршрутизирует линии привязки вокруг всех препятствий. На крайне плотных схемах возможны длинные линии; при уменьшении масштаба метки уменьшаются вместе со схемой, отдельной экранной агрегации нет.

## Проверка

Unit-тесты воспроизводят задачу с двумя соседними boundary events, внешнюю подпись, длинные счётчики, независимые плоскости, контейнер и занятое окружение. Electron проверяет реальные границы трёх бейджей и фигур в обеих темах, рост счётчиков, сохранение DOM при обновлении и совпадение координат SVG с холстом. Существующие проверки SVG/PNG и жестов колёсика выполняются повторно.
