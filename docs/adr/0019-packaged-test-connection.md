# 0019. Подключение UI-тестов к готовому приложению

Статус: принято. Дата: 2026-10-09. Дополняет [ADR 0013](0013-github-actions-release.md).

## Контекст

При подготовке 0.3.0 первый CI прошёл, а повторный прогон завершился timeout в проверках AppImage и Windows EXE. Сбой происходил в `electronApplication.firstWindow()` до UI-assertions. Локальная серия повторов также воспроизвела его.

Диагностика main показала `ready=true`, `isPackaged=true` и видимое окно с URL `bpmn-desk://app/`. Renderer имел `document.readyState=complete`, загруженный интерфейс и схему; CDP `/json/list` содержал page target. При этом Playwright сообщал ноль окон. Это сбой обнаружения окна в тестовом клиенте, а не отсутствие окна приложения.

## Решение

`tests/e2e/packaged-window` ждёт настоящее главное окно и завершение его навигации через публичные события Electron. Затем читает локальный `DevToolsActivePort` из изолированного тестового профиля и подключает UI через публичный [chromium.connectOverCDP](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp).

ElectronApplication продолжает запускать реальный executable и проверять main: packaged-режим, отсутствие no-sandbox, IPC, native сохранение и закрытие. CDP Page относится к тому же существующему BrowserWindow; новое окно не создаётся, страница не перезагружается. Browser/CDP соединение закрывается перед процессом Electron. При ошибке сохраняются состояние окна и stderr процесса.

Адаптер используется только для AppImage и win-unpacked. Обычные Electron-тесты остаются на стандартном API. Runtime-код, сборка и sandbox приложения не меняются. Debugging-порт включается существующим тестовым launcher, а не обычным запуском приложения.

## Альтернативы и последствия

Увеличение timeout или retries не исправляли бы пропущенный target. Добавление внутреннего loader Playwright было проверено и не устранило сбой; зависимость от внутренних файлов SDK не принята. Test-only задержка/ветка в main приложения также не нужна.

CDP подключается после реальной загрузки документа, поэтому проверяет уже созданное окно через поддерживаемый API. Имена контролов и все содержательные проверки сохранены. Новых зависимостей нет. До изменения воспроизводился сбой обнаружения окна; после изменения 20 последовательных локальных запусков AppImage прошли. Адаптер проверен на Linux и Windows в [CI 37991882513](https://github.com/michaelbrylevskii/bpmn-desk/actions/runs/37991882513) и повторно в релизной матрице 0.3.0.
