# 0021 — Общие вкладки, контролы и экспорт состояния

Статус: принято. Дополняет [0020](0020-runtime-connections.md) и [0011](0011-recovery-and-hidden-tabs.md).

## Контекст

Нужно одновременно сравнивать экземпляры разных серверов, сохранять рабочий контекст монитора при редактировании локальной копии и использовать общие команды приложения. Отдельный режим монитора и второй тулбар усложняют навигацию. Длинные идентификаторы и нативные select нарушают согласованность панелей.

## Решение

Общая модель вкладок содержит только тип, ID и ID подключения для монитора. Жизненный цикл документов остаётся в `documents`, состояние чтения — в отдельных экземплярах `RuntimeMonitor`. Скрытые вкладки остаются смонтированными, сохраняют холст, фильтры и выбор. Автоопрос работает только у активной вкладки и при видимом окне. Открытие файлов активирует документ отдельной ревизией; изменение модели или закрытие другого документа не переключает пользователя из монитора.

«Новая вкладка» предлагает профиль локальной схемы, подключение для монитора, встроенные примеры и недавние файлы. Списки файлов общие со стартовой страницей и доступны при открытых вкладках. Недавние перечитываются при открытии диалога, включая файлы, сохранённые без изменения числа документов. Выбор открывает или активирует документ через существующий жизненный цикл; черновики открытого файла не перезагружаются. Список подключений и их редактор общие. Последний выбранный профиль сохраняется как предпочтение; экземпляры, снимки и мониторные вкладки между запусками не восстанавливаются. Команды тулбара зависят от активной вкладки; доступность экспорта определяется готовностью просмотра. Поиск и прямой переход по ID экземпляра находятся в каталоге экземпляров.

После сохранения профиля повторяется чтение каталогов и снимков связанных мониторов; остальные вкладки не пересоздаются. При ошибке повторного чтения XML сохраняется последняя схема того же определения, вместе с предупреждением.

Проверка подключения получает черновик формы, проверяет его в main и выполняет только GET. Она не сохраняет профиль, пароль или токен. Существующий секрет можно использовать только при неизменных адресе, авторизации и username; изменённые поля проверяются как введены. API списка уже содержит имя определения, дополнительных запросов на каждую строку нет. Для списка дочерних процессов снимок делает отдельную paginated выборку по `superProcessInstanceId`; ошибки доступа и неполнота явно отмечаются.

Общий `Select` использует combobox/listbox с Arrow/Home/End, поиском по первым буквам, Enter, Escape и Tab. Popup живёт в ближайшем dialog или body, чтобы не обрезаться панелями и оставаться в модальном слое. Свойства BPMN передают выбор в существующий command stack. Новые UI-зависимости не требуются.

Runtime-экспорт сериализует SVG активной плоскости, заменяет переменные темы, переносит видимые маркеры и бейджи в SVG-графику и расширяет границы изображения. Selection outlines и hit areas удаляются. PNG использует общий адаптер растеризации. XML, DI и история документа не меняются; состояние исполнения не попадает в локальную копию BPMN.

## Альтернативы

- Пересоздание монитора при переключении вкладок: теряет выбор, фильтры и viewport. Отклонено.
- Кнопки монитора во второй панели: дублируют общий тулбар и занимают место холста. Отклонено.
- Сохранение формы перед проверкой: изменяет профиль до подтверждения работоспособности. Отклонено.
- Скриншот холста для PNG: зависит от масштаба и обрезает схему; скрывает различие между состоянием и UI. Отклонено.
- Подмена BPMN DI ради экспорта: загрязняет модель данными исполнения. Отклонено.

## Последствия

Открытые мониторы расходуют память на отдельные viewer и снимки. Фоновый автоопрос выключен, но уже отправленный запрос может завершиться; его устаревший результат игнорируется. Сортировка ограничена полями, поддержанными конкретным REST API. Runtime Camunda 7 по-прежнему не реализован. SVG/PNG содержит данные схемы и её текущие метки, выбранный момент чтения не является транзакционно согласованным снимком сервера.

Проверки используют независимый Flowable/H2: несколько вкладок, несохранённый документ и XML, формы подключения, дочерние экземпляры, фильтры, длинные строки, выделение и фокус, SVG/PNG с метками и отсутствие изменений BPMN. Общие listbox проверяются также на свойствах Flowable/Camunda и смене языка.
