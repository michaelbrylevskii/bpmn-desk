# 0014. Профили Flowable и Camunda 7

Статус: принято. Дата: 2026-10-09. Дополняет ADR 0003.

## Контекст

Поддержка второго движка требует отделить формы и диагностику от сериализации. Совпадающие имена атрибутов и тегов двух движков имеют разную семантику. Префиксы XML произвольны, идентичность определяется URI. Camunda 7.24 — целевая версия для независимой проверки; поддержка Camunda 8 и преобразование между движками в эту задачу не входят.

## Решение

- Общие пространства имён и команды generic XML находятся в `renderer/bpmn`. Реестры форм движков — в `renderer/flowable` и `renderer/camunda`; состав профилей — в `renderer/engines`.
- Сохраняем generic representation для обоих движков. Не регистрируем typed descriptor Camunda: неизвестные будущие и проектные теги того же URI должны сохраняться. Новых JavaScript runtime-зависимостей не требуется.
- Формы открытой схемы определяются по использованным URI. Если расширений ещё нет, учитываются объявления namespace; обычный BPMN не получает диагностику конкретного движка. При смешанных расширениях доступны оба профиля без автоматического преобразования XML.
- При создании выбирается BPMN, Flowable или Camunda 7; профиль сохраняется объявлением namespace в XML, а не отдельным локальным состоянием документа.
- Редактирование дерева расширений заменяет только адресованный узел и его предков одной командой. Неизвестные соседние атрибуты и дочерние узлы сохраняются. Undo использует исходное дерево.
- Совпадающие retry/listener/field теги различаются по URI. Коллизии префиксов разрешаются выбором свободного имени; чужие объявления не перепривязываются.
- `bpmn/model-copy` участвует в штатных replace/copy-paste командах: копирует `$attrs` и глубоко клонирует generic XML. При вставке глобальный ID `camunda:errorEventDefinition` заменяется уникальным; ID полей формы и неизвестных данных сохраняются. Применимые глобальные ID перечисляются в реестре движков.
- Свойства event definitions и multi-instance редактируются на вложенном BPMN target, с уведомлением исходного shape и той же историей команд. Формы ошибок definitions используют общий namespace-адаптер.

## Альтернативы

`camunda-bpmn-moddle` и `camunda-bpmn-js-behaviors` дают типизированную модель и готовые Camunda behaviors, но меняют обработку неизвестных элементов того же URI. Общий generic XML оставляет существующую гарантию сохранности и одинаковую модель обоих движков. Собственная реализация визуального BPMN не требуется: недостающие операции копирования дополняются событиями bpmn-js, стандартный command stack сохраняется.

## Проверка и ограничения

Roundtrip и UI-тесты проверяют оба профиля, альтернативные префиксы, вложенные структуры, смешанные расширения и undo/redo. Дополнительная проверка Java использует официальную Camunda BPMN Model API 7.24.0 (Apache-2.0) только как инструмент разработки. Java и движок не включаются в приложение.

Формы не запускают скрипты, Java delegates и процессы. Model API проверяет XML и модель, но не заменяет deployment в настроенный движок. Неизвестные расширения доступны через дополнительные атрибуты и XML; наличие формы не означает проверки произвольного пользовательского кода. Смешанные схемы сохраняются и редактируются, но совместимость с одним конкретным движком не гарантируется.
