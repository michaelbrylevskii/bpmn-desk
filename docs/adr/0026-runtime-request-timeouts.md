# 0026 — Таймаут подключения и медленные списки

Статус: принято.

## Контекст

Flowable REST 7.2 возвращает страницу вместе с `total`. В [PaginateListUtil](https://github.com/flowable/flowable-engine/blob/flowable-7.2.0/modules/flowable-common-rest/src/main/java/org/flowable/common/rest/api/PaginateListUtil.java) подсчёт выполняется на сервере после чтения страницы; исключение — неполная первая страница. Стандартного параметра отключения count нет. Даже небольшая страница может превысить фиксированный таймаут при большой базе или нагрузке.

## Решение

- В профиле подключения хранится таймаут запроса: целое число от 5 до 120 секунд. Значение по умолчанию — прежние 15 секунд; старые профили нормализуются при загрузке.
- Бюджет охватывает подключение и чтение body. Он применяется и к проверке черновика; renderer не управляет таймаутом отдельных запросов.
- Общий deadline сводки версии остаётся 8 секунд и имеет приоритет над более долгим таймаутом подключения.
- Автоматических повторов и обхода всех страниц для получения списка нет.
- При обновлении сохраняется успешная страница того же запроса, с явной пометкой во время загрузки и при ошибке. Ключ результата включает подключение, ревизию настроек, вид списка, фильтры и страницу; данные другого запроса не переиспользуются. Поздние ответы не применяются.

## Альтернативы и последствия

Глобальное увеличение таймаута скрывало бы задержки у всех пользователей. Исключение `total` только из интерфейса не устраняет серверный count. Настройка позволяет дождаться медленного ответа, но не оптимизирует SQL и не отменяет уже начатый запрос в БД. Для устранения стоимости count требуется серверная оптимизация или отдельный API без подсчёта.
