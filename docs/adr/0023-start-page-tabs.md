# 0023 — Стартовая страница как содержимое новой вкладки

Статус: принято. Дата: 2026-10-10. Заменяет модальный выбор новой вкладки из ADR 0015 и соответствующую часть ADR 0021.

## Контекст

Главная страница и диалог новой вкладки предлагали разные действия: монитор был доступен только в диалоге. Отдельные реализации расходились по оформлению и возможностям. Стартовая страница должна быть одинаково доступна до первого документа и из открытых документов/мониторов.

## Решение

«Новая вкладка», кнопка «+», Ctrl+N и native меню открывают обычную вкладку типа `home`. Её содержимое — тот же `Welcome`, что показывается при отсутствии вкладок: шапка, восстановление и `WorkspaceLauncher`. Последний отвечает за открытие файла, создание схемы, выбор подключения и открытие монитора, примеры и недавние файлы. Модальный `NewDiagramDialog` удалён. Кнопка создания со стрелкой раскрывает меню BPMN 2.0 / Flowable / Camunda 7; выбор сразу создаёт документ. Escape закрывает меню, пустая вкладка закрывается обычной кнопкой вкладки.

После успешного действия из стартовой вкладки её позицию занимает документ или монитор. Отмена выбора файла и ошибка чтения сохраняют стартовую страницу. Уже открытый файл активируется без дубликата и без перезагрузки черновика; исходная стартовая вкладка удаляется. При открытии нескольких файлов первый занимает стартовую вкладку, остальные открываются отдельно, активируется последний. Восстановление recovery сохраняет все документы.

Для асинхронного открытия ID исходной стартовой вкладки захватывается до чтения. Если её закрыли, поздний ответ открывает документ отдельно и не заменяет другую стартовую вкладку. `documents` возвращает ID открытых документов; порядок и замена содержимого остаются обязанностью `workspace`. Чистые функции `tab-state` проверяют порядок, сверку документов, дубликаты и закрытие; `use-tabs` связывает их с React. Внешнее открытие через CLI сохраняет обычное поведение без предположений об исходной стартовой вкладке.

Редакторы и мониторы не размонтируются при переходе на стартовую страницу. Сохраняются модель, XML-черновик, undo, выбранный экземпляр и viewport. Неактивный монитор приостанавливает опрос. Пустые вкладки не содержат модель, не помечают приложение изменённым и не входят в recovery.

Перед открытием стартовой вкладки активное поле теряет фокус, чтобы введённое значение попало в модель. Команды сохранения, экспорта и управления холстом на стартовой странице не применяются к скрытому документу.

Профили подключений загружаются и на главной странице: это чтение локальных настроек, без обращения к движку. Недавние файлы перечитываются при переходе на стартовую страницу. Настройка подключения использует существующий диалог; сохранение возвращает на ту же страницу с выбранным профилем. Браузерное preview оставляет монитор недоступным. Ошибки профилей показываются в блоке подключения.

Меню создания имеет семантику команд `menu/menuitem`, клавиатурный фокус, Arrow/Home/End, Escape и закрытие при клике снаружи. Popup находится в portal и не обрезается прокруткой страницы. Переключатель языка остаётся общим Select из ADR 0008 с одной кнопкой и одной рамкой фокуса.

## Альтернативы

- Синхронизировать две страницы вручную: отклонено из-за повторного расхождения возможностей.
- Сохранить модальный выбор поверх документа: отклонено в пользу стартовой вкладки.
- Показывать три отдельные кнопки движков: отклонено в пользу одной команды создания с явным раскрытием меню.
- Пересоздавать редактор после стартовой страницы: отклонено из-за потери черновиков и истории.

## Проверки и границы

Проверяются одинаковые действия начальной страницы и новой вкладки, создание трёх профилей, клавиатура меню, замена вкладки, отмена открытия файла, recent/пример/drop, сохранение соседнего черновика и монитора, recovery, обе темы и локали. На Linux проверяются Electron и AppImage; новые Windows/macOS проверки без запуска на этих ОС не заявляются.
