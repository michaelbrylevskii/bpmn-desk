# 0013. Проверки и релизы в GitHub Actions

Статус: принято. Дата: 2026-10-09.

## Контекст

Первая публичная поставка должна соответствовать опубликованному коду и по возможности собираться вне машины разработчика. Windows требует проверки на самой ОС, а локальные пользовательские пакеты не должны попадать в CI или артефакты.

## Решение

Один workflow выполняет проверки на push основной ветки, pull request и вручную. Матрица использует Ubuntu 24.04 и Windows Server 2022, Node.js 24 и JDK 17. Обе платформы выполняют strict TypeScript, ESLint, unit-тесты, сборку, UI/Electron и независимую проверку Flowable. На Linux также запускается извлечённая AppImage, на Windows — собранный EXE. Проверяются только встроенные схемы.

Linux UI запускается через Xvfb. На временном Ubuntu runner разрешены unprivileged user namespaces для sandbox Electron; опция `--no-sandbox` не используется. Эта настройка находится только в CI и не меняет требования к машине пользователя.

Артефакты матрицы содержат только AppImage, NSIS installer и portable. Push тега `v<package.version>` после успешной матрицы создаёт черновик релиза, загружает три файла и SHA256SUMS, затем публикует релиз. Перед загрузкой скрипт проверяет имена, непустые файлы, соответствие версии/тега и наличие release notes. Для fallback можно использовать локальные сборки с теми же проверками состава и версии.

Actions закреплены полными SHA. Задачи сборки получают `contents: read`; право `contents: write` имеет только задача публикации на теге. Pull request не может запускать публикацию. Скрипты electron-builder по-прежнему используют `--publish never`.

`.gitattributes` закрепляет LF для текста, а XML встроенных примеров исключает из нормализации переводов строк. Поэтому Windows checkout сохраняет исходные байты и контрольные суммы provenance.

## Альтернативы

Только локальные сборки проще, но зависят от среды владельца. Только Linux-кросс-сборка Windows не проверяет нативный запуск. Выбраны две ОС с общими критериями успешности.

## Последствия

Первый запуск workflow проверяется на GitHub до выпуска тега. Проверка Windows Server 2022 не подтверждает ручную установку, удаление и ассоциации на Windows 10/11. Артефакты не подписаны; автоматическое обновление приложения не добавляется.

Иконка поставки использует тот же символ Workflow и палитру, что логотип интерфейса. Символ Lucide имеет ISC; полный текст лицензии включён в `licenses/`, фон и оформление — MIT.

Документация платформы: [GitHub-hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [события workflow](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows).
