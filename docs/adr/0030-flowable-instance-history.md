# 0030. История выполнения Flowable

## Контекст

Runtime API содержит только текущее состояние. Для разбора завершённых экземпляров, повторов и параллельных выполнений нужны исторические записи и точная версия развёрнутого BPMN.

## Решение

- История — режим существующего монитора, доступный из экземпляра. Каталог различает текущие экземпляры, завершённые и все доступные в истории. Runtime остаётся самостоятельным источником текущего состояния.
- Main предоставляет конкретные GET-операции `historicInstances` и `history` через проверяемый IPC. Renderer не получает произвольный HTTP-клиент. Контракты истории выделены в `shared/history`.
- Исторический снимок содержит метаданные экземпляра, отдельные выполнения activities, дочерние экземпляры и последние сохранённые переменные. Ошибка раздела сохраняет прочитанные данные и признак неполноты. Отсутствующая длительность остаётся `null`.
- Один снимок читает не более 1000 activities, 100 дочерних экземпляров и 100 переменных, страницами до 100 записей. После чтения метаданных разделы используют общий deadline из настроенного таймаута подключения. Повторов и обхода дочерних экземпляров нет.
- Activities запрашиваются по уникальному `activityInstanceId`, чтобы одинаковое время начала не создавало нестабильные границы страниц. Порядок отображения определяется временем; совпадение времени не устанавливает причинный порядок. Пагинация и повторяющиеся ID проверяются.
- Привязка выполняется по `activityId` к XML из точного `processDefinitionId`. Стрелки подсвечиваются только при наличии соответствующих записей `sequenceFlow`; маршрут не достраивается по соседним узлам.
- Повторы и multi-instance сохраняют собственные ID, execution, время и длительность. Выполненный activity не означает успешный результат: публичный REST 7.2 не возвращает причину удаления каждого activity. Причина удаления экземпляра показывается отдельно.
- Исторические переменные — последние сохранённые значения, не состояние на момент выбранного шага. Восстановление значений по времени, воспроизведение, административные операции и изменение движка не входят в эту итерацию.

Разделение режимов просмотра заменено общей схемой и вкладками подробностей в [ADR 0031](0031-unified-instance-monitor.md); контракты и ограничения исторических данных сохраняются.

## Последствия

Доступность зависит от уровня истории, прав, очистки и наличия deployment. Пустая история не доказывает, что процесс не выполнялся. Ограниченная выборка обозначается явно, включая счётчики повторов. Историческая запись без endTime означает отсутствие зафиксированного окончания, а не гарантированную текущую активность. Снимок не транзакционен; поздние ответы после смены экземпляра игнорируются. Runtime-метки и история не изменяют XML, dirty state и undo редактора.
