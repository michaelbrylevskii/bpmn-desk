# 0005. Файлы, IPC и восстановление

Статус: принято. Дата: 2026-10-08.

## Контекст

Локальное приложение должно сохранять привычные файлы, не затирать внешние изменения и защищать несохранённую работу. Renderer обрабатывает потенциально незнакомый XML и не должен иметь общий доступ к файловой системе.

## Решение

Main хранит file capabilities: случайный token, канонический путь и SHA-256 последней версии. Renderer передаёт token и текст, путь сохранения выбирается native dialog. Обычное сохранение сверяет хеш; конфликт требует переоткрыть файл или выбрать «Сохранить как». Временный файл создаётся рядом с целевым, записывается с flush и заменяет целевой через rename.

Локальное восстановление несохранённого XML и черновиков — localStorage профиля Electron. Восстановление не перепривязывает файловые tokens. При закрытии вкладки требуется подтверждение отказа от изменений; при закрытии окна сообщается о локальном восстановлении.

Перед закрытием окна main запрашивает prepare-close. Renderer снимает фокус с поля, экспортирует актуальные модели, синхронно сохраняет recovery и сообщает dirty state. Если renderer не ответил, закрытие требует подтверждения. Это защищает последний ввод, ещё не прошедший обычный onBlur.

## Альтернативы

Прямая запись renderer требует небезопасного расширения прав. Запись поверх файла без временной копии может повредить его при ошибке. Слежение только за mtime пропускает некоторые внешние изменения. Облачный backend противоречит локальной работе.

## Последствия

Проверка внешних изменений оптимистическая: другие приложения не обязаны соблюдать наши locks. LocalStorage имеет ограничение объёма; ошибку восстановления показываем явно, сохранение BPMN остаётся доступным. Поля формы применяются при потере фокуса; XML и XML расширений — явными кнопками. Форматирование исходника не сохраняется побайтово.
