# 0044 — Фоновая проверка версий

Статус: принято. Дата: 2026-11-10.

## Поведение

Собранное приложение проверяет последний стабильный релиз GitHub после загрузки первого окна и затем каждые шесть часов, пока приложение открыто. Проверка не задерживает интерфейс, открытие схем или работу монитора. Новые окна используют общее состояние и не запускают дополнительные запросы.

Если версия релиза новее установленной, существующий бейдж версии получает оранжевое оформление. Текст бейджа остаётся номером установленной версии; доступная версия и действие указаны в обычной подсказке приложения, доступной также с клавиатуры. Нажатие открывает страницу последнего релиза в системном браузере. Серый бейдж запускает проверку вручную. В обоих состояниях это одна кнопка с одинаковыми размерами, шрифтом, положением и запретом выделения текста; в узком окне она остаётся доступна.

Во время запроса по фону кнопки проходит мягкий блик; дополнительных значков и изменения размеров нет. Кнопка временно отключена, прозрачность и читаемость номера сохраняются; `aria-busy` сообщает о проверке. При настройке reduced motion фон остаётся статичным. Все окна разделяют статус и один выполняющийся запрос: ручные и автоматические проверки объединяются, повторный клик не создаёт дополнительного обращения к GitHub. Ручная проверка не меняет шестичасовой интервал.

Индикация длится минимум одну секунду с начала проверки. Быстрый ответ сохраняется до окончания этого интервала; медленный запрос не получает дополнительной задержки. Ожидание относится только к состоянию проверки версий, не задерживает работу приложения и отменяется при завершении. Таймаут сети по-прежнему десять секунд, без добавления секунды после него.

Сетевая ошибка, HTTP-ошибка, таймаут или некорректный ответ возвращают обычное серое оформление, включая случай, когда предыдущая проверка нашла обновление. Анимация прекращается, кнопка снова доступна; всплывающие уведомления и немедленные повторы не показываются. Подсказка использует один шаблон: заголовок результата, дата и время последней завершённой проверки, действие по нажатию. Она различает доступное обновление, отсутствие новых версий, ошибку и таймаут. «Новых версий не обнаружено» показывается только после успешного чтения корректных метаданных стабильного релиза. Во время нового запроса остаётся время предыдущего завершённого; первая проверка не показывает вымышленную дату. Время фиксируется по фактическому ответу, до минимального ожидания индикации, и выводится в локальной зоне и выбранной локали.

Состояние между запусками не сохраняется. Автоматической загрузки, установки и перезапуска нет; механизм одинаков для AppImage, Windows installer и portable.

## Границы и реализация

Отдельный сервис `src/desktop/updates` принадлежит main-процессу. Он выполняет публичный GET к фиксированному `https://api.github.com/repos/michaelbrylevskii/bpmn-desk/releases/latest` без авторизации и cookies. Настройки подключений к движкам, секреты и содержимое документов в запрос не включаются. Таймаут десять секунд охватывает заголовки и тело ответа; предел тела — 256 КиБ. Redirect запрещён. Учитываются только корректные стабильные теги `vMAJOR.MINOR.PATCH` или `MAJOR.MINOR.PATCH`, строго новее установленной версии; draft и prerelease отвергаются. Сравнение числовое, а не строковое.

Контракты статуса, подписки, ручной проверки и открытия релиза находятся в `src/shared/updates.ts`; preload предоставляет отдельный `window.updates`. Renderer не выполняет сетевые запросы и не задаёт внешние URL. Main открывает только фиксированную HTTPS-страницу релизов текущего репозитория, если обновление доступно. IPC принимает вызовы только из главного frame зарегистрированного окна. Подписки удаляются при закрытии окон, запрос и периодический таймер прекращаются при завершении приложения.

По умолчанию в режиме разработки автоматическая проверка отключена, ручная доступна по кнопке; в browser-preview запроса к GitHub нет; сервис и UI проверяются изолированными ответами. Для ручной проверки dev-запуск Electron принимает `VITE_BPMN_DESK_DEV_VERSION=0.0.0`: корректная версия `MAJOR.MINOR.PATCH` подменяет номер в шапке и сравнение, а также включает настоящий запрос GitHub. `package.json` не изменяется; собранное приложение игнорирует переменную. Дополнительные зависимости и настройки не требуются. Семантика endpoint описана в [GitHub REST API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release).

## Проверка

Unit-тесты проверяют выбор версий, периодичность, общее состояние, таймауты заголовков и тела, ограничения ответа, ошибки и восстановление после них. UI-тесты проверяют подсказку, обе темы, клавиатуру, открытие релиза, возврат к серому оформлению и согласование начального snapshot с событиями. Итоговые команды и результаты фиксируются в [протоколе](../validation-updates.md).
