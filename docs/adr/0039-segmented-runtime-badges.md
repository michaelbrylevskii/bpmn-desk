# 0039 — Секции бейджа истории, runtime и ошибок

Статус: принято. Дата: 2026-10-30. Дополняет ADR 0037–0038: счётчики сохраняют семантику, меняется их совместное представление.

## Решение

У BPMN ID один бейдж, содержащий отдельные секции слева направо: история (серая), runtime (зелёная), dead-letter (красная). Внешний контур скруглён, соседние цвета соединены небольшим зигзагом глубиной 3px. При наличии одного значения видна одна секция. Символы `◷`/`✓`, `●`, `!` сохраняют читаемость без опоры только на цвет. Неполнота каждой выборки обозначается собственным `N+`.

Модель хранит тип и подпись каждой секции отдельно от цвета обводки узла. Ошибка больше не вытесняет известный runtime-счётчик. Приоритет обводки остаётся прежним: dead-letter, runtime, история. Неизвестные значения не становятся нулевыми секциями. Счётчики могут пересекаться, складывать их нельзя; это поясняется в подсказке легенды.

В сводке история — разные экземпляры с зарегистрированным шагом, runtime — разные экземпляры у элемента, ошибки — разные экземпляры с dead-letter. В снимке экземпляра история сохраняет число зафиксированных окончаний, runtime — executions, ошибки — задания. Отдельная историческая метка без зарегистрированного окончания сохраняет оранжевое обозначение и многоточие; оно не становится подтверждённой runtime-позицией.

HTML использует последовательность секций с перекрытием и clip-path. SVG строится из той же модели, палитры и ширин: полигоны зигзага, общий clipPath со скруглением, отдельные текстовые значения. PNG получается из этого SVG. ID clipPath не конфликтуют с исходными SVG ID. Экспорт не зависит от CSS приложения. Общая подпись сохраняется для доступности; декоративные секции скрыты от повторного озвучивания.

Неизменившийся бейдж сохраняет DOM. Число HTML overlays не растёт: одна группа на элемент, жесты колёсика проходят к холсту. XML и command stack схемы не изменяются. Новых зависимостей нет.

## Проверка

Unit-тесты проверяют три независимых счётчика, дедупликацию и `N+`, порядок секций, цвета и полигоны SVG. Electron проверяет сочетание трёх источников в сводке и снимке экземпляра, обе темы и ширины 1500/1050, SVG/PNG и цвета пикселей, увеличение над бейджем, сохранение DOM при обновлении. Независимый Flowable проверяет реальные executions, dead-letter, историю и экспорт.
