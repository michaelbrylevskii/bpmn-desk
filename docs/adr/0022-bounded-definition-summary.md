# 0022 — Ограниченная сводка выбранной версии процесса

Статус: принято; значение фильтра последних версий изменено в [ADR 0033](0033-monitor-catalog-search.md). Дата: 2026-10-10.

## Контекст

Каталог определений показывает версии BPMN, а не состояние отдельных экземпляров. Для диагностики полезно увидеть экземпляры и dead-letter на общей схеме версии. Полный обход экземпляров, переменных и страниц может создавать сотни запросов к медленному серверу. Flowable REST 7.2 не предоставляет общего агрегата по элементам и фильтров определений «с экземплярами»/«с dead-letter».

## Решение

Сводка загружается только явным действием «Сводка версии». Для точного `processDefinitionId` выполняются параллельно ровно два GET: первая страница `runtime/executions` и первая страница `management/deadletter-jobs`, по 100 записей. Общий deadline — 8 секунд, включая чтение HTTP body. Нет дочитывания страниц, запросов на каждый экземпляр, переменных, повторных попыток или автоматического опроса сводки. Для каждого ответа сохраняется прежнее ограничение 16 МБ. Серверная страница сверх лимита или с другим offset считается недостоверной.

Лимиты ограничивают клиентское чтение и объём получаемых данных. Прерывание HTTP не гарантирует немедленную остановку SQL на стороне сервера; инструмент не управляет серверными таймаутами. Это дополнительная причина оставлять сводку явным действием, без фонового опроса.

Сводка не блокирует холст и навигацию. Повторное чтение одного монитора недоступно, пока его запросы не завершились. При смене версии, профиля, уходе со вкладки или размонтировании запоздавший ответ игнорируется. Уже отправленные HTTP-запросы завершаются либо прерываются deadline; мгновенная отмена через отдельный IPC не вводится. При возврате к вкладке сохранённая сводка показывает своё время; обновление остаётся явным. При повторном чтении прежние бейджи убираются, чтобы не выдавать прошлое состояние за новое.

Состояние чтения принадлежит монитору, а не пересоздаваемому viewer: переход к другой версии не позволяет запустить несколько параллельных сводок в той же вкладке. При изменении размеров окна и панелей viewer сохраняет центр и масштаб; скрытие вкладки с нулевым размером не пересчитывает положение холста. Обычное обновление снимка сохраняет viewer и выделение.

Бейдж версии считает различные `processInstanceId` у элемента: несколько executions одного экземпляра не увеличивают счётчик. Красный бейдж считает различные экземпляры с dead-letter, а не количество заданий. При наличии executions и ошибок в одном элементе приоритет имеет красный счётчик. Позиция задания берётся из `elementId` либо уже полученного execution; дополнительных запросов ради неизвестной позиции нет. Неразмещённые задания обозначаются отдельно. Зелёный бейдж не означает, что процесс прямо сейчас исполняется на CPU: он может ожидать, быть приостановлен или иметь ошибку в другой ветви.

При выборе элемента правая панель показывает связанные экземпляры из уже полученной выборки. Повторяющиеся ID объединяются; локальная пагинация по 10 строк не обращается к API. Переход к экземпляру с dead-letter сразу открывает его раздел ошибок. Полный снимок экземпляра загружается только после этого явного перехода. Список не обогащается business key отдельными запросами; пустая выборка элемента не выдаётся за отсутствие экземпляров на сервере.

Полная первая страница даёт точный счётчик в пределах отдельного ответа. При усечении используются нижние границы `≥ N`; `N+` не применяется, поскольку дополнительные записи могут относиться к другим элементам. Для недоступного раздела сохраняется ошибка, а не фиктивный ноль. Отсутствие метки в неполной сводке не означает отсутствие экземпляров или ошибок. Общая сводка не является транзакционно согласованным снимком. SVG/PNG сохраняет показанные счётчики; экспорт не дополняет данные запросами и не изменяет XML.

Фильтр «Только последние версии» использует штатный `latest=true`, по умолчанию выключен. Старые определения могут обслуживать экземпляры и содержать ошибки. Список экземпляров не содержит статусных точек и Active/Suspended. Открытие правой панели даёт состояние приостановки и сведения о dead-letter из снимка. Active не означает отсутствие ошибок или выполнение прямо сейчас. По UX-ревью исключена индикация, которая смешивала приостановку с ошибками; вариант изменения цвета только после клика также отклонён как непоследовательный. Дополнительные запросы ради проверки каждой строки не выполняются.

## Альтернативы и границы

- Полные снимки каждого экземпляра и обход всех страниц отклонены из-за нагрузки и задержек.
- Автоматическая сводка при открытии каждой версии отклонена: сетевой бюджет должен быть явным.
- Глобальные фильтры «только с экземплярами/ошибками» и красные метки в каждой строке определения не вводятся. Фильтрация только текущей страницы дала бы неверные общие результаты и пагинацию.
- Отдельный серверный агрегат мог бы дать полноценную статистику, но потребовал бы установки компонента у пользователя. На этом этапе используется стандартный REST API.

Проверки покрывают дедупликацию multi-instance, частичный доступ, огромный total, лимиты ответа, зависание до заголовков и во время body, отсутствие дополнительных запросов, поздний ответ после навигации, экспорт, `latest=true` с ключом и поиском по имени на независимом Flowable 7.2/H2.
