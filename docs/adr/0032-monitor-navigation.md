# 0032. Переходы назад и вперёд в мониторе

## Контекст

Отдельная строка возврата занимала высоту схемы и поддерживала только возврат из дочернего экземпляра. Каталог, связанные процессы и задания должны иметь одинаковую навигацию, а подсказка — различать назначения с одинаковым названием схемы.

## Решение

- Каждый монитор хранит собственные текущий адрес, предыдущие и следующие переходы. Адрес — точная версия определения, экземпляр или dead-letter job. Новое назначение после возврата удаляет следующую ветку. Повторное открытие адреса не создаёт дубль.
- Правая вкладка «Текущее состояние»/«История» сохраняется с адресом. Её переключение, выбор элемента, фильтры и обновление снимка не создают переходов. История ограничена 100 адресами в каждом направлении и хранится только в памяти; смена подключения сбрасывает её.
- Кнопки находятся в общем тулбаре только для монитора и выключены, если назначения нет. Подсказка содержит тип назначения, название схемы/версию, business key или имя и ID. Используются уже загруженные сведения; наведение не вызывает сетевых запросов. При отсутствии имени это обозначается явно.
- Боковые кнопки мыши передаются через `BrowserWindow.app-command` (`browser-backward`, `browser-forward`) и существующий канал действий. Команда обрабатывается только активным монитором. Редактор, стартовая страница и диалог подключений не меняют навигацию. Browser history и URL приложения не используются.
- Отдельная полоса возврата над схемой удалена. Легенда и время снимков отображаются по одной строке; дополнительные пояснения доступны в подсказках по наведению и фокусу, закрываются Escape и не обрезаются панелями.

## Последствия

Переход читает свежие снимки через обычные ограниченные операции; навигация не хранит копии engine-ответов, не меняет движок и не затрагивает undo редактора. Для большого числа адресов самые старые записи отбрасываются. Удалённый экземпляр или deployment может стать недоступен, но ссылка в истории остаётся для повторного чтения.

Системные команды мыши документированы Electron для Linux и Windows; macOS требует отдельного решения и не объявляется поддержанной этой доработкой. Автоматический Linux-тест отправляет `app-command` в настоящее окно Electron и проверяет весь путь до активного монитора; физическое устройство этим не проверяется.
