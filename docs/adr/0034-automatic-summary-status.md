# 0034 — Автосводка и компактный статус в мониторе

Статус: принято. Дата: 2026-10-30. Дополняет [ADR 0022](0022-bounded-definition-summary.md): заменяет явную первую загрузку, отсутствие опроса и очистку данных при обновлении. Бюджет каждого чтения и семантика счётчиков сохранены.

Уточнение после следующей локальной проверки: [ADR 0035](0035-monitor-filter-tabs-and-panel-scroll.md).

Уточнение следующей итерации: [ADR 0036](0036-shared-definition-context.md) заменяет копии контекста; [ADR 0037](0037-global-summary-and-history.md) заменяет настройку и бюджет сводки, добавляет history и постоянную панель.

## Решение

Сводка автоматически загружается при открытии точного определения. Настройка `autoSummary` принадлежит подключению, включена по умолчанию, в том числе для существующих профилей без поля. Она валидируется в main и сохраняется вместе с профилем без изменения секретов. При выключенной настройке загрузка начинается по нажатию иконки или общего обновления. Общий авторефреш сам по себе не включает отключённую первую загрузку; после ручной загрузки он поддерживает сводку этой версии в актуальном состоянии.

Постоянная иконка статистики в заголовке схемы получает индикатор загрузки, успеха, неполноты или ошибки. Подсказка с наведением/фокусом и закрытием Escape показывает прочитанное/общее количество записей, время, легенду, ограничения и ошибки. Отдельной полосы сводки нет. Клик загружает ещё не прочитанную сводку или повторяет полную ошибку; после загрузки переключает метки на схеме. Общая кнопка обновления выполняет повторное чтение, в том числе для определения. Скрытие меток не отключает установленный авторефреш.

Для активного определения общий авторефреш выполняет чтение через 5 секунд после завершения предыдущего. Неактивные вкладки и скрытое окно новых чтений не запускают. Переключение авторефреша не отменяет уже начатый запрос. Очередь принадлежит монитору и сохраняется при переходах между определениями: новое чтение ждёт завершения прежнего; ответ прежней версии/профиля/неактивного монитора не применяется. Уже отправленные HTTP завершаются в пределах своего deadline; отдельного IPC отмены нет.

Каждое чтение по-прежнему ограничено двумя GET, первыми страницами по 100 записей, общими 8 секундами и лимитом ответа 16 МБ. Обхода страниц, запросов на каждый экземпляр и немедленных повторов после ошибок нет. При включённом авторефреше следующая попытка проходит в обычном цикле. Клиентский deadline не гарантирует остановку серверного SQL; настройка автозагрузки и общий переключатель позволяют ограничивать нагрузку.

Во время обновления доступна предыдущая сводка. При полной ошибке сохраняются её данные и исходное время с явной отметкой устаревания. При ошибке одного раздела доступная часть нового ответа показывается как неполная с ошибкой источника; неизвестное количество не становится нулём. Нижние границы и неразмещённые задания остаются видны в подсказке. Иконка не смешивает ошибку чтения с наличием dead-letter в данных.

Viewer не пересоздаётся при обновлении снимков. Маркеры и бейджи сравниваются по BPMN ID, типу и подписи: неизменившиеся DOM-элементы сохраняются, удаляются/создаются только затронутые. Изменение времени снимка само по себе не меняет меток. Выбор, масштаб, прокрутка и страницы подробностей сохраняются средствами стабильных компонентов и ключей.

## Проверки

Сценарии Electron проверяют автоматическую/ручную загрузку, настройки и миграцию профиля, обновление по таймеру, отсутствие чтения скрытой вкладки, очередь при смене определения, частичные/устаревшие данные, сохранение DOM бейджа, выбора, масштаба, прокрутки и страницы подробностей. Независимый Flowable проверяет смысл счётчиков, ограничения выборки и экспорт.
