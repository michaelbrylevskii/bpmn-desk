# 0009. Сборки Windows и среда кросс-сборки

Статус: принято. Дата: 2026-10-09. Дополняет [0006](0006-distribution-and-validation.md).

## Контекст

Нужны готовые Windows-сборки существующего редактора. Разработка и текущая проверочная среда работают на Linux; на настоящей Windows запуск пока недоступен.

## Решение

Поставляем Windows x64 в двух форматах electron-builder: NSIS installer с выбором каталога и standalone portable EXE. У форматов разные имена файлов. Установщик работает для текущего пользователя без повышения привилегий и предлагает English/Русский. Его язык не меняет настройку языка приложения. Ассоциация предусмотрена для `.bpmn`; открытие `.bpmn20.xml` и `.xml` доступно из приложения и через CLI.

Portable означает запуск без установки: содержимое распаковывается во временный каталог, а пользовательские настройки и recovery используют обычный профиль Electron. Переносимый профиль рядом с EXE отдельно не реализуется. Обе сборки содержат один и тот же application payload, копии примеров и иконку.

На Windows используется `npm run package:windows`. На Linux с Wine доступна та же команда; без системного Wine используется `npm run package:windows:docker`. Последняя компилирует приложение на Linux-хосте и упаковывает его в официальном образе `electronuserland/builder:24-wine`, зафиксированном по digest. Контейнер получает только каталог проекта, работает с UID/GID разработчика и не публикует порты. Все сборочные кеши, включая профиль Wine, расположены в `.cache/`; пользовательские файлы снаружи проекта не монтируются. NSIS toolset зафиксирован на 1.2.1 (NSIS 3.12).

Кеш скачанных инструментов получает отдельный `package.json` с `type: commonjs`, чтобы CommonJS-скрипт конвертации PNG → ICO не наследовал ESM-режим репозитория. Runtime приложения остаётся ESM. Новые npm-зависимости не добавляются.

Vite в обоих dev-режимах исключает `.cache/`, `release/` и `test-results/` из наблюдения. Профиль Wine содержит ссылки на корень файловой системы контейнера; после сборки они не должны обходиться dev-сервером на хосте.

Проверка поставки разделена на целостность архивов/состав и запуск. На Linux проверяются внешние NSIS-контейнеры, вложенный 7z payload, PE x64, наличие main/preload/renderer в ASAR, иконки и копий примеров. Добавлен Playwright-проект `windows` для проверки готового приложения на Windows: CLI-путь с кириллицей и пробелами, sandbox/preload, поиск XML, язык, изменение Flowable-свойства, сохранение и bundled examples. На Linux этот тест пропускается.

## Альтернативы

- Только NSIS: требует установки даже для быстрой ручной проверки. Поэтому добавлен portable.
- Системная установка Wine на машине разработчика: допустима при наличии Wine, но Docker позволяет обойтись без изменения системы.
- Автозагрузка Wine toolset 1.0.1: в текущей среде bundle завершался ошибкой загрузки `ntdll.dll`, поэтому выбран официальный Docker-образ с рабочим Wine.
- CI на Windows: полезен после появления remote/CI; сейчас проект остаётся локальным.

## Последствия

Готовые EXE не подписаны сертификатом издателя. Кросс-сборка не доказывает работоспособность Windows UI, установки, удаления или файловых ассоциаций. Эти сценарии требуют проверки на Windows; инструкция находится в [windows.md](../windows.md). macOS и Windows ARM64/ia32 не входят в эту поставку.
