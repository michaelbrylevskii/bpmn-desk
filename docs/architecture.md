# Архитектура

## Ответственности

| Модуль | Отвечает за | Не отвечает за |
|---|---|---|
| `src/desktop` | Окно Electron, меню, IPC, файлы, недавние пути | BPMN-модель и UI |
| `src/shared` | Контракты IPC и общие ошибки | Electron, React, Node API |
| `src/renderer/platform` | Адаптер preload и браузерный preview | Моделирование |
| `src/renderer/documents` | Жизненный цикл документов, dirty state, сохранение, восстановление | Внутреннее устройство bpmn-js |
| `src/renderer/bpmn` | bpmn-js, команды, XML, диагностика, защита данных | Компоненты React и файловая система |
| `src/renderer/flowable` | Namespace, реестр форм, generic extensions Flowable | Electron и жизненный цикл вкладок |
| `src/renderer/camunda` | Формы, структуры расширений и диагностика Camunda 7 | Сериализация, Electron и жизненный цикл вкладок |
| `src/renderer/engines` | Контракты профилей, их состав и определение по URI | Переключение языка и файловая система |
| `src/renderer/properties` | Формы выбранного элемента и определения | Прямое изменение модели |
| `src/renderer/workspace` | Порядок и выбор вкладок, холст, поиск, панели XML/диагностики | Файловая система |
| `src/renderer/ui`, `styles` | Переиспользуемые элементы и оформление | BPMN-модель |
| `src/desktop/runtime` | Профили, секреты, ограниченный HTTP и Flowable REST, IPC | React и отображение схем |
| `src/renderer/runtime` | Каталог процессов, снимки экземпляров, панель переменных/jobs | HTTP, секреты и команды моделирования |

`bpmn`, `engines`, `flowable` и `camunda` используют общие типы BPMN, но не импортируют UI. Только BPMN-адаптер создаёт Modeler. Каждый документ получает собственный экземпляр и независимый command stack. Скрытые вкладки сохраняют историю и положение холста.

ESLint запрещает renderer доступ к `node:*`, Electron и desktop. Shared не зависит от renderer. TypeScript strict и noUncheckedIndexedAccess включены. ESLint ограничивает исходные модули 280 содержательными строками.

## Поток изменения

1. React-форма передаёт значение в BpmnEditor.
2. Адаптер валидирует значение и выполняет команду bpmn-js.
3. Command stack публикует изменение; адаптер экспортирует актуальный XML.
4. Документ сравнивает XML с последним сохранённым состоянием и обновляет локальное восстановление.
5. Перед сохранением повторно проверяются импортируемость и сохранность расширений.
6. Через preload передаются XML и токен файла. Main проверяет внешние изменения и атомарно заменяет файл.

## XML и сохранность данных

Flowable и Camunda namespaces не зарегистрированы как частичные moddle descriptors: unknown tags внутри известного namespace могут отбрасываться. Атрибуты хранятся в `$attrs`, вложенные элементы — в generic objects. Формы являются отдельным реестром и не определяют полноту сериализации.

Каноническое сравнение использует namespace URI, localName, атрибуты и текст. Префиксы и CDATA не считаются семантикой. Для generic-атрибутов того же namespace, что и тег, адаптер исправляет снятие prefix в moddle-xml. Mixed content, который модель не может сохранить, блокируется проверкой roundtrip.

PreservationGuard защищает исходные namespaced атрибуты и extensionElements при изменениях холста. Привязка к moddle-объектам сохраняется при смене ID и undo. Явное редактирование атрибута разрешает изменение этого ключа; редактирование extensionElements/их форм — блока расширений выбранного элемента. Удаление элемента считается явным удалением его метаданных.

Профиль определяется по использованным URI; для пустых схем — по объявлениям namespace. `bpmn/model-copy` дополняет штатные операции глубоким копированием generic extensions и `$attrs`. Глобальные ID известных расширений при вставке генерируются заново; остальные пользовательские данные сохраняются. Подробнее: [ADR 0014](adr/0014-engine-profiles.md).

Видимый XML-черновик хранится отдельно от модели. Применение XML начинает новую историю команд. Ошибочный XML не заменяет текущую диаграмму. До применения или отмены XML-черновика сохранение BPMN блокируется.

## Офлайн и безопасность

Приложение не исполняет JavaScript/Java/expressions из BPMN. Локальный редактор работает без сети и CDN. Дополнительный монитор обращается только к выбранному REST API через main и конкретные операции GET; deployment и административные действия не предоставляются. Renderer изолирован, Node integration выключен; файлы и чтение движка доступны только через IPC. Проверяется отправитель IPC, окна/переходы/permissions запрещены. Production UI обслуживается собственным protocol с проверкой пути и CSP.

Восстановление хранит только несохранённые документы и XML-черновики в localStorage профиля Electron. После восстановления документ требует «Сохранить как»: старые токены и разрешения файловой системы не переносятся. Профиль и список недавних файлов принадлежат локальному пользователю ОС.

## Отображение и навигация

`desktop/interface-zoom` управляет Chromium zoom, меню и настройками профиля; BPMN viewport остаётся в адаптере. `bpmn/diagram-theme` отвечает за цвета отображения и самостоятельный SVG. `ui/xml-selection` хранит синтаксический диапазон выбранного ID и декорации CodeMirror, а `ui/code-editor` — ввод, поиск и переключение темы без пересоздания редактора.

`ui/use-theme` хранит предпочтение auto/light/dark и вычисляет палитру через matchMedia; `ui/theme-picker` отвечает за три кнопки выбора. `bpmn/xml-fragment-format` выравнивает копию extensionElements для панели свойств, сохраняя значимый текст/CDATA/xml:space и исходную модель.

`notifications/types` задаёт контракт результата действия и контекст ошибки; `notifications/errors` формирует сообщение из исключения. `documents/run` ловит ошибки операций, а `ui/notification-toast` отвечает за оформление. `ui/use-notice-dismiss` управляет временем жизни и паузой/задержкой возобновления; таймер не влияет на документы.

`bpmn/property-presence` дополняет штатный undo восстановлением отсутствующих собственных свойств. `bpmn/label-presence` возвращает исходную DI подписи и её bounds после завершающих событий undo, включая различия импортированной геометрии. Формы отображают заданные значения акцентной боковой гранью. `bpmn/boundary-layout` отделяет диагностику и чистый план координат от выполнения перемещений через стандартный modeling и command stack. React не меняет DI напрямую.

## Локализация

`shared/i18n` — чистые каталоги, тип языка, интерполяция и адаптер диагностических сообщений. `desktop/language-settings` хранит настройки профиля, `desktop/application-menu` формирует native меню. Язык передаётся через ограниченный bridge. Renderer `i18n/provider` отвечает за реактивный выбор, `i18n/search-phrases` — за phrase names CodeMirror.

Компактный поиск реализован в `ui/xml-search-panel` поверх команд CodeMirror; язык меняет его текст через конфигурацию EditorState без нового DOM/editor. BPMN-адаптер получает getter языка и обновляет инструменты событием i18n.changed. UI не переводит данные модели и не обращается к профилю на диске напрямую.

## Примеры и дополнительные проверки

Приложение использует только фиксированный каталог `examples/`: browser preview импортирует верхнеуровневые `.bpmn20.xml`, desktop читает этот же каталог из resources. Provenance и тексты лицензий сопровождают встроенные материалы. Исходные пользовательские пакеты не входят в renderer или поставку.

`scripts/lib/schema-pack` отвечает за структуру/пути/checksum/UTF-8 внешнего пакета; `tests/extra` — за roundtrip и UI; `scripts/test-extra` запускает их отдельно от основного набора. `scripts/validate-flowable` передаёт уже проверенные пути независимому Java-конвертеру. `scripts/validate-camunda` проверяет свои встроенные и изменённые экспорты через Model API 7.24. Общий `scripts/lib/java-validation` отвечает только за запуск Maven/Java; семантические проверки остаются в отдельных Java-инструментах. Все выходы дополнительных проверок лежат в `.cache/`; входы не изменяются. Dev-сервер не наблюдает и не отдаёт `.cache/` и `.local-schemas/`.

`bpmn/image-export` растрирует самодостаточный SVG в PNG через Chromium. `ui/export-menu` выбирает формат; bridge передаёт текст или Uint8Array, main атомарно сохраняет экспорт отдельно от capabilities документов и recent files. Новая схема создаётся через меню `ui/create-diagram-menu` единой стартовой страницы; документ получает явно выбранный профиль.

`scripts/capture-screenshots` создаёт browser preview встроенной демонстрационной схемы в двух темах и двух локалях, используя временный Chromium profile.

`tests/e2e/packaged-window` подключает UI к существующему главному окну через публичный CDP после завершения навигации; main остаётся доступен через ElectronApplication. Этот тестовый адаптер не входит в дистрибутив и не добавляет hooks в приложение.

## Монитор движка

`desktop/runtime/connection-store` атомарно сохраняет метаданные и зашифрованные секреты профилей; временные секреты остаются в памяти main. `http` ограничивает методы, адрес, редиректы, время и объём ответа. `flowable-reader` реализует конкретные операции чтения, пагинацию и частичные снимки; `flowable-decode` проверяет ответы в контракты `shared/runtime`. Отдельный preload предоставляет только эти операции, без универсального proxy.

`renderer/workspace/use-tabs` хранит общий порядок документов, мониторов и стартовых вкладок. Чистые функции `tab-state` отвечают за сверку, замену и закрытие. `Welcome` и `WorkspaceLauncher` — единая стартовая страница до открытия контента и во вкладке `home`; создание схемы использует меню команд. `documents` возвращает ID открытого документа, а `workspace` заменяет исходную стартовую вкладку после успешного открытия. Документы остаются в `documents`, мониторы — в `runtime`; закрытие монитора не затрагивает черновики документов. `runtime/use-connections` загружает общие профили и помнит последнее подключение. `runtime/controls` передаёт возможности активного монитора общему тулбару. `runtime/workspace` связывает вкладку с профилем; `monitor` имеет отдельное состояние на вкладку и пересоздаётся при смене сервера или адреса/авторизации профиля. Старые ответы игнорируются. `use-snapshot` управляет последовательным опросом, временем снимка и ошибками; скрытый монитор не продолжает автообновление. Каталог, переменные, executions, jobs и диалог профилей выделены в самостоятельные компоненты.

`bpmn/runtime-viewer` создаёт NavigatedViewer, обрабатывает выбор и навигацию, добавляет маркеры и overlays. Он не вызывает команды моделирования и не сохраняет XML. Снимки не входят в `documents/recovery`; локальная копия создаётся через обычный жизненный цикл документа без данных исполнения. `bpmn/runtime-export` переносит видимые runtime-маркеры и HTML overlays в самодостаточный SVG текущей плоскости; общий PNG-адаптер растрирует его без снимка UI. Подробнее: [ADR 0020](adr/0020-runtime-connections.md) и [ADR 0021](adr/0021-workspace-tabs-and-runtime-export.md).

`tools/runtime-fixture` — независимое Spring Boot/Flowable/H2 приложение с оригинальными MIT-схемами. `scripts/test-runtime` собирает стенд, ожидает готовность реального dead-letter, запускает Electron E2E и завершает сервер. Никакие пользовательские сервисы или схемы основному набору не требуются; Java и стенд не включаются в ASAR или resources.

`ui/select` — общий combobox/listbox с клавиатурой и popup в ближайшем модальном dialog либо body. Его выбор передаётся через callback: свойства редактора продолжают использовать команды BPMN, формы подключений и фильтры меняют свои черновики. Нативные HTML select в UI не используются.
