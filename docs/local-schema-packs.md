# Дополнительные локальные схемы

Основные проверки и приложение используют встроенный `examples/`. Схемы конкретного пользователя подключаются отдельным пакетом только для дополнительного прогона. Их файлы не изменяются и не включаются в сборки.

## Формат

Храни пакет вне репозитория или в игнорируемом `.local-schemas/`:

Каталоги пакета и результатов не должны пересекаться. Runner проверяет это до очистки экспортов, в том числе для путей через символические ссылки. Не размещай пакет в `.cache/extra-schema-exports/` или `.cache/extra-test-results/`.

```text
my-schema-pack/
  schemas/
    process.bpmn20.xml
    approval.bpmn
  provenance.json
```

`provenance.json` — непустой JSON-массив:

```json
[
  {
    "file": "process.bpmn20.xml",
    "sha256": "<SHA-256 содержимого файла, 64 hex-символа>",
    "source": "описание локального источника"
  }
]
```

Обязательны `file` и `sha256`; дополнительные поля сохраняются в твоём пакете и не интерпретируются runner. Каждый `.bpmn`/`.xml` из `schemas/` должен иметь ровно одну запись. Имена содержат только имя файла без каталогов; ссылки за пределы пакета и повторяющиеся имена отклоняются. Сумма считается по исходным байтам, включая BOM, если он есть. Поддерживаются имена с кириллицей и пробелами.

После намеренного изменения собственной схемы обнови её SHA-256 в provenance. Runner никогда не переписывает manifest автоматически: несовпадение означает, что проверяемый вход изменился.

## Запуск

Linux:

```bash
BPMN_DESK_EXTRA_SCHEMAS=/absolute/path/to/my-schema-pack npm run test:extra
BPMN_DESK_EXTRA_SCHEMAS=/absolute/path/to/my-schema-pack npm run validate:flowable:extra
```

Windows PowerShell:

```powershell
$env:BPMN_DESK_EXTRA_SCHEMAS = 'C:\Local schemes\my-schema-pack'
npm run test:extra
npm run validate:flowable:extra
Remove-Item Env:BPMN_DESK_EXTRA_SCHEMAS
```

Для первой команды нужны npm dependencies и Chromium из `npm run setup:e2e`. Для второй дополнительно нужны JDK 17+ и Maven. Необходимо сначала выполнить `test:extra`: он создаёт входные экспорты для конвертера.

`test:extra` выполняет checksum/provenance, двойной XML roundtrip и UI-открытие/сохранение каждого файла. Для отсутствующего DI UI-тест явно пропускается; roundtrip и экспорт выполняются. Ошибка импорта, предупреждение о потерянных данных или изменение расширений делают проверку неуспешной. `validate:flowable:extra` сравнивает исполняемые модели оригиналов и экспортов; DI исключён, Java delegates/expressions не исполняются.

Экспорты: `.cache/extra-schema-exports/`; UI traces и ошибки: `.cache/extra-test-results/`. Они могут содержать исходный XML, поэтому предназначены для локального использования. Новый прогон очищает предыдущие дополнительные экспорты. Только после успешного roundtrip и UI-прогона записывается `completed.json` с checksum входов и экспортов; конвертер отклонит отсутствующий результат, другой пакет или изменённый экспорт. Обычные `check`, `test:e2e` и `validate:flowable` не зависят от установленной переменной и продолжают проверять встроенный набор.

Пакет не добавляет примеры в welcome screen. Для ручной работы открой его схему стандартной командой Open / Открыть. Если репозиторий переносится, отдельно перенеси пакет и обнови путь в переменной.
