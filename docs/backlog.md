# Бэклог

Актуальный следующий план — **MON-09–MON-14** в конце документа. Он согласован, но реализация **ожидает отдельной отмашки пользователя**. Первые два раздела описывают уже выполненные итерации.

## UX монитора Flowable после 0.6.0

Зафиксировано 30 октября 2026 года. Пользователь дал отмашку на реализацию. Все восемь пунктов реализованы локально; финальные проверки и ручное ревью отмечаются в [протоколе](validation-monitor-ux.md). Ниже сохранены исходные пожелания и обсуждённые варианты до реализации; описания прежнего поведения относятся к состоянию на момент составления бэклога. Принятые решения — в [ADR 0033](adr/0033-monitor-catalog-search.md) и [ADR 0034](adr/0034-automatic-summary-status.md).

Принято: `Definitions / Определения`, последние версии по умолчанию, отдельные условия каталогов на время жизни монитора, поиск с выбором критерия, обе контекстные ссылки, сводка варианта B и несколько независимо раскрываемых записей истории.

### MON-01. Терминология

Переименовать вкладку `Processes` в название каталога определений. Выровнять терминологию в обеих локализациях: вкладки, заголовки, поля, подсказки, доступные имена и документация.

Предложение для обсуждения:

| English | Русский | Значение |
| --- | --- | --- |
| Process definition; Definitions | Определение процесса; Определения | Развёрнутое определение в движке |
| Process instance; Instances | Экземпляр процесса; Экземпляры | Конкретный запуск |
| Diagram | Схема | Визуальное представление |
| Definition ID / key / version | ID / ключ / версия определения | Различать эти поля |
| Summary | Сводка | Статистика по определению |

Обсудить русский вариант: «Определения» или «Дефиниции». Не использовать неоднозначное «ID процесса», когда речь об ID определения или экземпляра.

### MON-02. Последние версии по умолчанию

В каталоге определений фильтр последних версий включён изначально. Пользователь может явно запросить все версии. Предлагаемое поведение сброса фильтров — возвращаться к последним версиям.

Это ограничение списка, а не подмена версии открытого экземпляра: текущий или исторический экземпляр всегда показывает своё точное определение, включая старую версию.

Обсудить срок сохранения пользовательского выбора: переключения вкладок каталога, подключений, перезапуск приложения. Не включать фильтр заново при каждом действии пользователя.

### MON-03. Единый поиск и фильтры

Переработать левую панель определений, экземпляров и заданий: один узнаваемый блок поиска, дополнительные фильтры, понятные активные условия и сброс. Согласовать расположение элементов, пагинацию, состояния загрузки и ошибки. Убрать конкурирующие формы без понятной иерархии.

Отличать поиск от открытия по известному ID; явно обозначать точное совпадение и поиск по части строки. Поиск только по загруженной странице нельзя выдавать за поиск по всему каталогу.

Желаемый вариант — одно поле по нескольким атрибутам. До выбора UX проверить возможности API отдельно для определений, текущих и исторических экземпляров, заданий. Запасной вариант — одно поле с явным выбором критерия. Автоопределение UUID не должно мешать бизнес-ключам, похожим на ID.

Предварительная проверка Flowable 7.2.0: runtime API поддерживает дополнительные критерии имени и частичного бизнес-ключа, включая варианты без учёта регистра. Текущий адаптер использует лишь часть возможностей. В просмотренных runtime DTO и обработчике не найден универсальный OR по произвольным полям; это не вывод обо всех API Flowable. Наличие POST-запроса само по себе не означает поддержку OR. Текущий HTTP-адаптер приложения допускает только GET.

Источники: [параметры runtime GET](https://github.com/flowable/flowable-engine/blob/flowable-7.2.0/modules/flowable-rest/src/main/java/org/flowable/rest/service/api/runtime/process/ProcessInstanceCollectionResource.java), [DTO запроса](https://github.com/flowable/flowable-engine/blob/flowable-7.2.0/modules/flowable-rest/src/main/java/org/flowable/rest/service/api/runtime/process/ProcessInstanceQueryRequest.java), [применение условий](https://github.com/flowable/flowable-engine/blob/flowable-7.2.0/modules/flowable-rest/src/main/java/org/flowable/rest/service/api/runtime/process/BaseProcessInstanceResource.java), [REST-документация](https://www.flowable.com/open-source/docs/bpmn/ch14-REST).

Объединение нескольких запросов требует решения для дубликатов, сортировки, общего количества, пагинации и нагрузки. Не обещать такой поиск до проверки этих условий.

### MON-04. Строки списка и контекстные переходы

Сделать строки единообразными по смыслу: основное название, контекст, метаданные и идентификатор. Не заполнять отсутствующие поля пустыми строками ради одинаковой высоты.

Предложение: перенести ссылку на экземпляры из строки определения в заголовок над схемой, сразу после имени и версии. Ссылка открывает экземпляры именно выбранного определения и версии; область фильтра должна быть видна в каталоге.

Уточнить направление пользовательской «ссылки на процессы»: определение → экземпляры, экземпляр → определение или оба. Обратный переход должен вести к точной версии, а не к последней.

### MON-05. Сводка без лишней панели

Два варианта для обсуждения:

| Вариант | Поведение |
| --- | --- |
| A | Кнопка работает как переключатель компактной панели; сводка очищена от постоянных длинных пояснений |
| B, предпочтение пользователя | Автозагрузка после открытия определения; постоянная иконка статистики с небольшим индикатором загрузки, успеха или ошибки; цифры и легенда в содержательной подсказке; отдельной панели нет |

Для варианта B: настройка автозагрузки в подключении, по умолчанию включена. Общий авторефреш обновляет и сводку. Подсказка доступна с клавиатуры; если нужны интерактивные действия, использовать подходящее всплывающее окно.

Состояния должны различать отсутствие загрузки, загрузку, полные и частичные данные, ошибку и устаревший результат. Ошибка получения сводки отличается от наличия проблемных заданий. Частичную выборку нельзя показывать как полную статистику, неизвестное количество — как ноль.

Исходное ограничение (заменено ADR 0037): два запроса первых страниц по 100 записей с общим сроком ожидания 8 секунд. Это ограниченная выборка, а не серверная агрегация всех экземпляров. Сохранить смысл нижних границ `≥`, свежести и частичных ошибок в компактном представлении. Таймаут клиента не гарантирует остановку SQL на сервере.

Автозагрузка сейчас намеренно отсутствует согласно [ADR 0022](adr/0022-bounded-definition-summary.md). После согласования нового поведения оформить изменение решения в ADR; текущий документ не меняет действующее ограничение.

Требования к обновлениям:

- Обновлять активный видимый монитор без перекрывающихся запросов и полного обхода страниц; отбрасывать запоздалые ответы при смене подключения или определения.
- Предложение: при ошибке обновления сохранять предыдущую сводку с отметкой устаревания.
- Не пересоздавать схему и панели при неизменившихся данных. Сохранять прокрутку, выделение, раскрытые записи и масштаб; изменение только времени получения не должно перестраивать все маркеры.
- При изменениях обновлять затронутое содержимое. Сейчас начало загрузки сводки убирает предыдущие данные — нужное поведение ещё не обеспечено.

Обсудить: окончательный вариант A/B; действие клика по иконке; ручное обновление и повтор после ошибки; скрытие отметок на схеме; взаимодействие выключенной автозагрузки с включённым авторефрешем; период обновления и значение настройки для существующих подключений.

### MON-06. Подсветка XML в мониторе

Использовать существующий XML-компонент на CodeMirror с темами и режимом только чтения, без новой зависимости. Учесть просмотр XML при отсутствии графической части BPMN.

Просмотр не изменяет XML, модель, признак несохранённых изменений или стек отмены. Не сбрасывать прокрутку и текстовое выделение, если XML не изменился.

### MON-07. Заметное выделение элемента

Усилить выделение в мониторе при выборе на схеме и из истории. Выделение должно читаться независимо от цветов текущего состояния, ошибок и истории, не подменяя их смысл.

Проверить светлую и тёмную темы, стрелки, маленькие и граничные события, вложенные элементы и бейджи. Выбор не раскрывает скрытую правую панель автоматически.

### MON-08. Раскрытие истории без неожиданной фильтрации

Клик по записи истории раскрывает её; при необходимости фокусирует и выделяет элемент на схеме, но не меняет фильтр журнала, не скрывает соседей и не сбрасывает прокрутку. Прямой клик по элементу схемы сохраняет возможность фильтрации истории по нему, включая повторные посещения. Сброс фильтра — явный. Раскрытие другой записи не снимает уже заданный фильтр.

Разделить состояния выбранного элемента схемы, фильтра истории по элементу и раскрытой записи по ID исторической активности. Программный фокус из журнала не должен восприниматься как прямой пользовательский клик по схеме. Сейчас эти действия связаны общим выбором элемента, что и вызывает неожиданную фильтрацию.

Обсудить одну или несколько одновременно раскрытых записей: несколько полезны для сравнения повторных проходов одного элемента.

### Результат согласования

1. Терминология и единый поиск приняты; поиск остаётся серверным, без объединения страниц разных запросов.
2. Условия сохраняются между каталогами и режимами истории в текущем мониторе, без сохранения на диск. Сброс возвращает последние версии.
3. Контекстные ссылки работают в обе стороны и используют точный ID определения.
4. Выбран вариант B. Клик по загруженной сводке переключает метки; общее обновление перечитывает данные. После полной ошибки клик повторяет загрузку. При выключенной автозагрузке авторефреш работает после ручного первого чтения. Настройка включена для существующих подключений.
5. Записи истории раскрываются независимо; выделение, фильтр и раскрытие разделены. XML подсвечен и доступен только для чтения.

Дополнительный поиск через OR по нескольким полям оставлен как возможное будущее развитие после проверки подходящего серверного API. Реализация не публикуется без отдельного запроса пользователя.


## Уточнения после локальной проверки — 2026-10-30

Согласованы и реализованы локально по повторной отмашке пользователя:

- Цветовая легенда только над схемой; из подсказки сводки удалена. Загрузка схемы не зависит от сводки.
- Вместо пары «критерий + поиск» все отдельные API-фильтры размещены в сворачиваемом блоке. Заполненные условия применяются вместе; отображаются одинаковыми съёмными чипами, включая предфильтр версии определения.
- Каталоги runtime и history разделены на вкладки. У каждой независимые условия; состояние завершения history — обычный фильтр. Выбор строки задаёт начальную правую вкладку, общая схема и ручное переключение источников сохранены.
- Выделение приближено к редактору: тонкая сплошная рамка без тени.
- Справа один скролл для карточки и содержимого; отдельный скролл списка убран. При малой высоте окна журнал не сжимается под карточкой.

Решение: [ADR 0035](adr/0035-monitor-filter-tabs-and-panel-scroll.md). Ручная проверка пользователя и публикация выполняются отдельно; разрешения на push этой доработки нет.

## Следующая итерация монитора — согласованный план

Дата согласования: 2026-10-30. **Статус: выполнено локально по отмашке пользователя; ожидается ручная проверка.** Push и релиз требуют отдельного запроса. Согласованное поведение MON-09–MON-14 реализовано нижеописанными решениями; итоговые проверки фиксируются в `docs/validation-monitor-ux.md`.

Решения: [ADR 0036](adr/0036-shared-definition-context.md), [ADR 0037](adr/0037-global-summary-and-history.md). Они заменяют независимые копии контекста, настройку автосводки в подключении и фиксированный бюджет 8 секунд из ADR 0034–0035.

### MON-09. Общий контекст определения

- Переход «Экземпляры» из определения задаёт один общий контекст точной версии для каталогов Runtime, History и Dead-letter jobs. Не создавать три независимых копии фильтра.
- Показывать контекст тем же компактным чипом с названием и версией, но спокойного фиолетового оттенка в обеих темах. Добавить значок связи и доступную с клавиатуры подсказку «Общий для Runtime, History и Dead-letter jobs», чтобы смысл не зависел только от цвета.
- Переключение каталогов сохраняет контекст. Крестик в любой из трёх вкладок снимает его сразу для всех. Каталог определений этот контекст не ограничивает.
- «Сбросить фильтры» в одном из этих трёх каталогов снимает общий контекст везде, а остальные условия сбрасывает только у текущего каталога. Условия других каталогов сохраняются; их пагинация должна учитывать изменение общего контекста.
- Локальные бизнес-ключи, даты, статусы и остальные условия остаются независимыми. Не допускать скрытого второго ограничения по другой версии определения.
- Срок жизни общего контекста — текущий монитор и подключение; в отличие от переключателя сводки, сохранение контекста после перезапуска не вводится.

### MON-10. Постоянный переключатель сводки

- Иконка сводки в заголовке схемы становится полноценным переключателем. Включённое состояние выделено рамкой и фоном; `aria-pressed` отражает включённость функции, в том числе во время загрузки и после ошибки.
- Маленький индикатор загрузки, успеха, неполноты или ошибки показывается только при включённой сводке. В выключенном состоянии остаётся обычная иконка без статусного бейджа.
- Одно состояние переключателя принадлежит приложению, одинаково во всех мониторах и подключениях и сохраняется после перезапуска. Настройку автосводки из формы подключения убрать.
- При миграции один раз использовать настройку активного подключения как начальное значение, включая явно сохранённое `false`. Если такой настройки нет, сохранить действующее значение по умолчанию — включено. Уже сохранённое глобальное значение имеет приоритет над миграцией. Далее источником состояния служит только глобальная настройка. Старые профили должны читаться без потери остальных параметров и секретов.
- При включении сводка загружается для выбранного определения и автоматически для последующих определений. Общий авторефреш обновляет её только при включённом переключателе; скрытые вкладки и скрытое окно не инициируют новые чтения.
- Выключение скрывает метки и останавливает последующие автоматические чтения. Ответ уже отправленного запроса не включает переключатель и метки обратно. Не блокировать возможность выключить функцию во время загрузки.
- Ручное обновление и повтор после ошибки выполняются общей кнопкой обновления при включённой сводке; нажатие самой иконки всегда переключает функцию, а не меняет смысл в зависимости от результата загрузки.

### MON-11. История в сводке определения

- В правой панели выбранного элемента определения добавить вкладки `Runtime / Текущее состояние` и `History / История`. Термин «Активные» не использовать: runtime включает приостановленные экземпляры, а history может содержать продолжающиеся процессы.
- Runtime показывает экземпляры с текущей позицией на элементе и связанные dead-letter jobs. History показывает экземпляры с зарегистрированным проходом этого элемента в доступной выборке истории. Один экземпляр может присутствовать в обоих списках.
- Считать разные экземпляры по каждому BPMN-элементу; повторные проходы и multi-instance одного экземпляра не увеличивают его счётчик. Это отличается от журнала отдельного экземпляра, где сохраняются отдельные проходы.
- На схеме добавить отдельный счётчик истории. Не складывать его с runtime; текущие позиции и dead-letter сохраняют приоритет обводки. Историческая метка не означает успешное завершение.
- Переход из списка Runtime открывает правую вкладку текущего состояния экземпляра, из History — вкладку истории. Вручную переключать источник по-прежнему можно.
- Загружать историю одним дополнительным GET по точному `processDefinitionId`, до 1000 записей исторических шагов, начиная со свежих. Сохранить выборки до 100 executions и 100 dead-letter jobs. Нет обхода всех страниц, всех экземпляров и отдельных запросов на каждый элемент или строку списка; подробности экземпляра читаются при его открытии.
- Ограничение относится к записям шагов, а не к числу разных экземпляров: цикл одного процесса может занять большую часть выборки. При неполноте показывать `≥ N`, отсутствие элемента описывать как отсутствие в загруженной выборке, а не отсутствие проходов вообще. `total` исторических шагов не выдавать за общее количество экземпляров.
- Полнота, ошибки и свежесть различаются для каждого источника. Недоступная история не скрывает runtime и наоборот. Отключённую, загружающуюся или недоступную сводку не изображать как успешно загруженный пустой список.

Возможность общего запроса и сортировки проверена по исходникам Flowable 7.2: [historic activity GET](https://github.com/flowable/flowable-engine/blob/flowable-7.2.0/modules/flowable-rest/src/main/java/org/flowable/rest/service/api/history/HistoricActivityInstanceCollectionResource.java), [фильтр определения и сортировка](https://github.com/flowable/flowable-engine/blob/flowable-7.2.0/modules/flowable-rest/src/main/java/org/flowable/rest/service/api/history/HistoricActivityInstanceBaseResource.java). При реализации проверить запрос на независимом Flowable-стенде проекта.

### MON-12. Единые сведения экземпляра

- Привести общие поля правых вкладок Runtime и History к одному представлению, порядку и формату дат в выбранной локализации. Заголовок и идентификатор экземпляра отображаются одинаково.
- Порядок: движок, состояние, начало, окончание и длительность при наличии, определение, tenant, инициатор и причина прекращения при наличии. Специфичные поля добавляются на своих местах без перестановки общих полей.
- Убрать спойлер «Подробности экземпляра» ради двух полей; ID определения и Tenant ID показывать в общем плоском блоке.
- ID определения сделать ссылкой на его точную развёрнутую версию с обычной навигацией назад/вперёд. Не подменять её последней версией.
- Смысл состояния зависит от источника: отсутствие окончания в history не означает подтверждённую активность runtime; отсутствие данных не превращается в успешное завершение.
- Связанные экземпляры сохраняют общий шаблон Parent/Child. Правая панель по-прежнему прокручивается целиком, без отдельного скролла списка.

### MON-13. Стабильная правая панель определения

- При просмотре определения правая панель присутствует постоянно и имеет одинаковую ширину при выбранном элементе и без выбора.
- Без выбранного элемента показывать «Выберите элемент для просмотра подробностей». Клик по фону возвращает этот плейсхолдер, не меняя ширину схемы и панели.
- Выбор элемента показывает его вкладки Runtime/History и соответствующее состояние сводки.
- Сохранить сворачивание язычком. Выбор элемента не раскрывает свёрнутую панель; сохраняются мягкая однократная подсветка язычка и отметка обновления. Без выбора плейсхолдер не должен запускать дополнительные запросы.

### MON-14. Таймаут сводки из подключения

- Убрать отдельный фиксированный бюджет 8 секунд. Использовать настройку таймаута API текущего подключения: существующие диапазон 5–120 секунд и значение по умолчанию 15 секунд сохраняются.
- Три источника сводки читаются параллельно с единым бюджетом одной загрузки, включая чтение тела ответа. Это не три последовательных таймаута и не полный обход страниц.
- При истечении бюджета сохранить успешно полученные части и указать недоступные источники; неизвестные значения не заменять нулём. Сохранить поведение устаревших данных при ошибке обновления.
- Лимиты записей и размера ответа сохраняются. Загрузка и отображение схемы, работа холста и просмотр XML не зависят от завершения сводки.

### Порядок реализации и проверки после отмашки

1. Оформить ADR по общему контексту, настройке сводки и расширению её источников. Реализовать общий фильтр с чипом и независимыми локальными условиями.
2. Добавить глобальный переключатель с сохранением и миграцией старой настройки, убрать контрол из подключения и связать бюджет чтения с таймаутом подключения.
3. Добавить ограниченную историю сводки, раздельные счётчики и вкладки подробностей элемента; стабилизировать правую панель определения.
4. Унифицировать сведения экземпляра и переход по ID определения. Обновить обе локализации, README и описание ограничений/API.
5. Проверить общий сброс контекста, сохранение независимых условий и корректную пагинацию; состояние переключателя во всех мониторах и после перезапуска; миграцию `false`; выключение во время загрузки; отсутствие чтений скрытых мониторов.
6. Проверить историю точной версии, свежие записи, повторы/multi-instance, отдельные счётчики, лимиты 100/100/1000 и частичные ошибки; заданные в подключении короткий и длинный таймауты; независимость отображения схемы и отбрасывание поздних ответов.
7. Проверить одинаковый порядок/формат полей, ссылку на точную версию, постоянную ширину панели при выборе и сбросе, сворачивание язычком, обе темы и локализации. Обновления должны сохранять DOM неизменившихся меток, выбор, масштаб, страницы и прокрутку.
8. Перед сдачей реализации выполнить `npm run check`, `npm run test:e2e`, `npm run package:linux` и соответствующие сценарии независимого Flowable-стенда. Передать пользователю локальную сборку для ручной проверки; публикацию не начинать без отдельного запроса.
