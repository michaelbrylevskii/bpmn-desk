# Бэклог

## UX монитора Flowable после 0.6.0

Зафиксировано 30 октября 2026 года. Пользователь дал отмашку на реализацию. Все восемь пунктов реализованы локально; финальные проверки и ручное ревью отмечаются в [протоколе](validation-monitor-ux.md). Ниже сохранены исходные пожелания и обсуждённые варианты до реализации; описания прежнего поведения относятся к состоянию на момент составления бэклога. Принятые решения — в [ADR 0033](adr/0033-monitor-catalog-search.md) и [ADR 0034](adr/0034-automatic-summary-status.md).

Принято: `Definitions / Определения`, последние версии по умолчанию, отдельные условия каталогов на время жизни монитора, поиск с выбором критерия, обе контекстные ссылки, сводка варианта B и несколько независимо раскрываемых записей истории.

### MON-01. Терминология

Переименовать вкладку `Processes` в название каталога определений. Выровнять терминологию в обеих локализациях: вкладки, заголовки, поля, подсказки, доступные имена и документация.

Предложение для обсуждения:

| English | Русский | Значение |
| --- | --- | --- |
| Process definition; Definitions | Определение процесса; Определения | Развёрнутое определение в движке |
| Process instance; Instances | Экземпляр процесса; Экземпляры | Конкретный запуск |
| Diagram | Схема | Визуальное представление |
| Definition ID / key / version | ID / ключ / версия определения | Различать эти поля |
| Summary | Сводка | Статистика по определению |

Обсудить русский вариант: «Определения» или «Дефиниции». Не использовать неоднозначное «ID процесса», когда речь об ID определения или экземпляра.

### MON-02. Последние версии по умолчанию

В каталоге определений фильтр последних версий включён изначально. Пользователь может явно запросить все версии. Предлагаемое поведение сброса фильтров — возвращаться к последним версиям.

Это ограничение списка, а не подмена версии открытого экземпляра: текущий или исторический экземпляр всегда показывает своё точное определение, включая старую версию.

Обсудить срок сохранения пользовательского выбора: переключения вкладок каталога, подключений, перезапуск приложения. Не включать фильтр заново при каждом действии пользователя.

### MON-03. Единый поиск и фильтры

Переработать левую панель определений, экземпляров и заданий: один узнаваемый блок поиска, дополнительные фильтры, понятные активные условия и сброс. Согласовать расположение элементов, пагинацию, состояния загрузки и ошибки. Убрать конкурирующие формы без понятной иерархии.

Отличать поиск от открытия по известному ID; явно обозначать точное совпадение и поиск по части строки. Поиск только по загруженной странице нельзя выдавать за поиск по всему каталогу.

Желаемый вариант — одно поле по нескольким атрибутам. До выбора UX проверить возможности API отдельно для определений, текущих и исторических экземпляров, заданий. Запасной вариант — одно поле с явным выбором критерия. Автоопределение UUID не должно мешать бизнес-ключам, похожим на ID.

Предварительная проверка Flowable 7.2.0: runtime API поддерживает дополнительные критерии имени и частичного бизнес-ключа, включая варианты без учёта регистра. Текущий адаптер использует лишь часть возможностей. В просмотренных runtime DTO и обработчике не найден универсальный OR по произвольным полям; это не вывод обо всех API Flowable. Наличие POST-запроса само по себе не означает поддержку OR. Текущий HTTP-адаптер приложения допускает только GET.

Источники: [параметры runtime GET](https://github.com/flowable/flowable-engine/blob/flowable-7.2.0/modules/flowable-rest/src/main/java/org/flowable/rest/service/api/runtime/process/ProcessInstanceCollectionResource.java), [DTO запроса](https://github.com/flowable/flowable-engine/blob/flowable-7.2.0/modules/flowable-rest/src/main/java/org/flowable/rest/service/api/runtime/process/ProcessInstanceQueryRequest.java), [применение условий](https://github.com/flowable/flowable-engine/blob/flowable-7.2.0/modules/flowable-rest/src/main/java/org/flowable/rest/service/api/runtime/process/BaseProcessInstanceResource.java), [REST-документация](https://www.flowable.com/open-source/docs/bpmn/ch14-REST).

Объединение нескольких запросов требует решения для дубликатов, сортировки, общего количества, пагинации и нагрузки. Не обещать такой поиск до проверки этих условий.

### MON-04. Строки списка и контекстные переходы

Сделать строки единообразными по смыслу: основное название, контекст, метаданные и идентификатор. Не заполнять отсутствующие поля пустыми строками ради одинаковой высоты.

Предложение: перенести ссылку на экземпляры из строки определения в заголовок над схемой, сразу после имени и версии. Ссылка открывает экземпляры именно выбранного определения и версии; область фильтра должна быть видна в каталоге.

Уточнить направление пользовательской «ссылки на процессы»: определение → экземпляры, экземпляр → определение или оба. Обратный переход должен вести к точной версии, а не к последней.

### MON-05. Сводка без лишней панели

Два варианта для обсуждения:

| Вариант | Поведение |
| --- | --- |
| A | Кнопка работает как переключатель компактной панели; сводка очищена от постоянных длинных пояснений |
| B, предпочтение пользователя | Автозагрузка после открытия определения; постоянная иконка статистики с небольшим индикатором загрузки, успеха или ошибки; цифры и легенда в содержательной подсказке; отдельной панели нет |

Для варианта B: настройка автозагрузки в подключении, по умолчанию включена. Общий авторефреш обновляет и сводку. Подсказка доступна с клавиатуры; если нужны интерактивные действия, использовать подходящее всплывающее окно.

Состояния должны различать отсутствие загрузки, загрузку, полные и частичные данные, ошибку и устаревший результат. Ошибка получения сводки отличается от наличия проблемных заданий. Частичную выборку нельзя показывать как полную статистику, неизвестное количество — как ноль.

Текущее ограничение: два запроса первых страниц по 100 записей с общим сроком ожидания 8 секунд. Это ограниченная выборка, а не серверная агрегация всех экземпляров. Сохранить смысл нижних границ `≥`, свежести и частичных ошибок в компактном представлении. Таймаут клиента не гарантирует остановку SQL на сервере.

Автозагрузка сейчас намеренно отсутствует согласно [ADR 0022](adr/0022-bounded-definition-summary.md). После согласования нового поведения оформить изменение решения в ADR; текущий документ не меняет действующее ограничение.

Требования к обновлениям:

- Обновлять активный видимый монитор без перекрывающихся запросов и полного обхода страниц; отбрасывать запоздалые ответы при смене подключения или определения.
- Предложение: при ошибке обновления сохранять предыдущую сводку с отметкой устаревания.
- Не пересоздавать схему и панели при неизменившихся данных. Сохранять прокрутку, выделение, раскрытые записи и масштаб; изменение только времени получения не должно перестраивать все маркеры.
- При изменениях обновлять затронутое содержимое. Сейчас начало загрузки сводки убирает предыдущие данные — нужное поведение ещё не обеспечено.

Обсудить: окончательный вариант A/B; действие клика по иконке; ручное обновление и повтор после ошибки; скрытие отметок на схеме; взаимодействие выключенной автозагрузки с включённым авторефрешем; период обновления и значение настройки для существующих подключений.

### MON-06. Подсветка XML в мониторе

Использовать существующий XML-компонент на CodeMirror с темами и режимом только чтения, без новой зависимости. Учесть просмотр XML при отсутствии графической части BPMN.

Просмотр не изменяет XML, модель, признак несохранённых изменений или стек отмены. Не сбрасывать прокрутку и текстовое выделение, если XML не изменился.

### MON-07. Заметное выделение элемента

Усилить выделение в мониторе при выборе на схеме и из истории. Выделение должно читаться независимо от цветов текущего состояния, ошибок и истории, не подменяя их смысл.

Проверить светлую и тёмную темы, стрелки, маленькие и граничные события, вложенные элементы и бейджи. Выбор не раскрывает скрытую правую панель автоматически.

### MON-08. Раскрытие истории без неожиданной фильтрации

Клик по записи истории раскрывает её; при необходимости фокусирует и выделяет элемент на схеме, но не меняет фильтр журнала, не скрывает соседей и не сбрасывает прокрутку. Прямой клик по элементу схемы сохраняет возможность фильтрации истории по нему, включая повторные посещения. Сброс фильтра — явный. Раскрытие другой записи не снимает уже заданный фильтр.

Разделить состояния выбранного элемента схемы, фильтра истории по элементу и раскрытой записи по ID исторической активности. Программный фокус из журнала не должен восприниматься как прямой пользовательский клик по схеме. Сейчас эти действия связаны общим выбором элемента, что и вызывает неожиданную фильтрацию.

Обсудить одну или несколько одновременно раскрытых записей: несколько полезны для сравнения повторных проходов одного элемента.

### Результат согласования

1. Терминология и единый поиск приняты; поиск остаётся серверным, без объединения страниц разных запросов.
2. Условия сохраняются между каталогами и режимами истории в текущем мониторе, без сохранения на диск. Сброс возвращает последние версии.
3. Контекстные ссылки работают в обе стороны и используют точный ID определения.
4. Выбран вариант B. Клик по загруженной сводке переключает метки; общее обновление перечитывает данные. После полной ошибки клик повторяет загрузку. При выключенной автозагрузке авторефреш работает после ручного первого чтения. Настройка включена для существующих подключений.
5. Записи истории раскрываются независимо; выделение, фильтр и раскрытие разделены. XML подсвечен и доступен только для чтения.

Дополнительный поиск через OR по нескольким полям оставлен как возможное будущее развитие после проверки подходящего серверного API. Реализация не публикуется без отдельного запроса пользователя.


## Уточнения после локальной проверки — 2026-10-30

Согласованы и реализованы локально по повторной отмашке пользователя:

- Цветовая легенда только над схемой; из подсказки сводки удалена. Загрузка схемы не зависит от сводки.
- Вместо пары «критерий + поиск» все отдельные API-фильтры размещены в сворачиваемом блоке. Заполненные условия применяются вместе; отображаются одинаковыми съёмными чипами, включая предфильтр версии определения.
- Каталоги runtime и history разделены на вкладки. У каждой независимые условия; состояние завершения history — обычный фильтр. Выбор строки задаёт начальную правую вкладку, общая схема и ручное переключение источников сохранены.
- Выделение приближено к редактору: тонкая сплошная рамка без тени.
- Справа один скролл для карточки и содержимого; отдельный скролл списка убран. При малой высоте окна журнал не сжимается под карточкой.

Решение: [ADR 0035](adr/0035-monitor-filter-tabs-and-panel-scroll.md). Ручная проверка пользователя и публикация выполняются отдельно; разрешения на push этой доработки нет.
