# Локальная проверка рабочих сессий и файлов

## Уточнения интерфейса от 2026-11-09

Решение: [ADR 0043](adr/0043-pinned-sessions-and-workspace-feedback.md). Код: `652d440` (вкладки), `9b006e2` (сессии), `8990c33` (экспорт). Версия локальной сборки остаётся 0.6.1; публикация не выполнялась.

`npm run check` — strict TypeScript, ESLint и 137 unit-тестов в 34 файлах успешно. `npm run package:linux` — AppImage x86_64 собрана. Полный `npm run test:e2e` — 125 passed, 19 ожидаемых skip за 4,6 минуты; включая 17 сценариев Electron и обе проверки AppImage. Пропуски: Windows и 18 сценариев отдельного движка, который в этой итерации не запускался; результат предыдущего независимого прогона сохранён ниже.

Проверяются именованные закрепления сверх лимита 15, чтение всех закреплений после перезапуска, переименование и отмена inline-ввода, обновление восстановленного рабочего набора, защита pin/имени от запоздалого автосохранения и пустое закрепление после закрытия вкладок. Проверки UI охватывают предложение только на главной, акцент несохранённых изменений, подписи мониторов с подключением, стрелки переполненных вкладок, постоянную доступность плюса и выбор клавиатурой. Оба PNG из меню Electron, прозрачность результата, действие уведомления и отмена экспорта проверяются нативно; сводки и экспорт монитора — на управляемых HTTP-ответах. API движка этой итерацией не изменён.

Просмотрены стартовая страница и подсказка сессии в светлой и тёмной темах. SHA-256 сборки: `ea56180eec93803fbe848a9abec4db2cdc226994c45f897c0564e21e7630935f`.

Для ручной приёмки: `npm run dev` или `release/BPMN-Desk-0.6.1-x86_64.AppImage`.

1. Закрепить сессию, задать имя в строке, отменить и повторить переименование. Проверить подсказки схем и мониторов, открепление и отдельное удаление.
2. Восстановить закрепление, изменить состав вкладок, перезапустить и восстановить его снова. Закрытие всех вкладок оставляет пустое именованное закрепление. Undo/Redo и цепочка навигации не восстанавливаются.
3. Открыть много вкладок, проверить стрелки и затухание краёв, выбор и перестановку клавиатурой, перетаскивание, доступность плюса. Плашка восстановления должна оставаться только на главной.
4. Экспортировать SVG и оба PNG из редактора и монитора, в том числе через меню по Alt. Нажать «Показать в папке» в уведомлении; проверить отмену диалога и временное скрытие уведомления.

Ручная приёмка пользователя ожидается. Windows/macOS в этой итерации не запускались.

| `npm run test:runtime` | Все 50 разных сценариев монитора/Flowable успешно проверены; подробности повтора ниже |

19 пропусков общего E2E — Windows и 18 сценариев отдельного движка. Все сценарии движка выполнены на независимом Flowable 7.2/H2. Общий runtime-прогон дал 49 passed и один сбой устаревшего тестового селектора стартовой страницы; проверка переведена на меню подключений. Повтор `npm run test:runtime -- tests/e2e/runtime.spec.ts --grep 'подключения: несколько'` — 1 passed. Код приложения при уточнении теста не менялся. Повторный `npm run check` также успешен.

Покрытие сессий: чистые и изменённые документы, порядок и активная вкладка, 21 фоновая схема, неприменённый XML, выбор и масштаб, изменения расширений и сохранение после восстановления. Проверяются миграция recovery, устойчивое скрытие предложения, удаление снимка с подтверждением и ограничение 15 записей. Ошибка чтения хранилища не разрешает его перезапись; ошибка записи при закрытии позволяет вернуться к документам.

Файловые сценарии включают изменение, возврат к прежнему содержимому, удаление и повторное создание, подтверждения отмены/копии/перезаписи, повторную проверку ревизии и сохранение модели при некорректном внешнем XML. Запись копии поверх уже открытого файла не меняет основу исходной вкладки: она получает внешний статус и предупреждение при сохранении. Меню проверяются клавиатурой и мышью; native copy/paste сохраняет отдельную отмену в целевой вкладке.

Несколько окон: восстановление из занятого окна, фокусировка уже открытой сессии, независимое закрытие, изоляция файловых tokens и команд меню, общие подключения с секретом в памяти, язык и тема. Изменение общего файла в одном окне обнаруживается другим. Мониторы восстанавливают фильтры и место просмотра, получают свежие ответы API; скрытый восстановленный монитор не загружается до открытия.

## Ручная проверка

Запуск из исходников: `npm run dev`. Локальная сборка: `release/BPMN-Desk-0.6.1-x86_64.AppImage`.

SHA-256 этой локальной AppImage: `d9c56cd63b910e48730da1b5d06360562bf306c0c7bc611d21995ad2d14e5045`.

1. Открыть несколько схем и мониторов, изменить схему и оставить XML без применения. Переставить вкладки, закрыть приложение и восстановить сессию; сравнить содержимое, выбор и активную вкладку.
2. Скрыть предложение восстановления, перезапустить приложение, затем восстановить запись из списка сессий. Проверить удаление записей обоих списков и доступность примеров из меню создания.
3. При открытых вкладках восстановить другую сессию: появляется отдельное окно, исходная работа сохраняется. Повторное открытие той же сессии переводит фокус в её окно.
4. Изменить и удалить открытый файл внешним редактором, проверить жёлтый и красный статусы с подсказками. Попробовать перезагрузку и все варианты сохранения при конфликте.
5. Проверить контекстное меню вкладок и меню по Alt, в том числе команды в разных окнах, обе темы и локализации.

Ручная приёмка пользователя ожидается. Windows/macOS в этой доработке не запускались. История undo между запусками и перенос фигур между окнами не сохраняются; буфер фигур общий для вкладок одного окна. Browser-preview использует localStorage с ограничениями браузера; проверка файлов и нативных окон выполняется в Electron. Пользовательские схемы и подключения не входят в Git или дистрибутив.
