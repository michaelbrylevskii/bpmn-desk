# Flowable REST: совместимость и ограничения

Возможности монитора описаны в [README](../README.ru.md). Здесь — условия подключения и смысл данных.

## API и авторизация

- Flowable REST 7.2: чтение repository/runtime/management/history через GET. Корень API обычно `/process-api/` или `/flowable-rest/service/`.
- Без авторизации, Basic или Bearer; тестирование использует черновик формы без сохранения профиля.
- OAuth/SSO, обновление токена, клиентские сертификаты и настройка proxy в UI не поддержаны. TLS-проверка включена, редиректы запрещены.
- Запросы выполняет Electron main через ограниченный IPC. Браузерный preview к движку не подключается; runtime Camunda 7 не реализован.

## Хранение

Профили находятся в `connections.json` пользовательского каталога Electron. Секрет — в памяти сессии либо, по выбору, в защищённом хранилище ОС. Backend `basic_text` не считается защищённым. Renderer получает только признаки наличия секрета.

Пустой секрет существующего профиля сохраняет текущий только при неизменных URL, авторизации и username. Смена этих полей не переносит секрет. Профили, ответы API и снимки не входят в Git или recovery документов. Между запусками сохраняется выбор подключения, но не открытые мониторы и экземпляры.

## Смысл состояния

| Данные | Семантика |
| --- | --- |
| Схема экземпляра | Его точный `processDefinitionId`, независимо от новых deployments |
| Active | Экземпляр не приостановлен; это не признак работы на CPU или отсутствия ошибок |
| Зелёный счётчик экземпляра | Executions с позицией в элементе, без родительских scope-контейнеров |
| Красный счётчик экземпляра | Связанные dead-letter jobs |
| Сводка версии | Разные экземпляры у элемента; multi-instance одного экземпляра считается один раз |
| `≥ N` | Нижняя граница неполной выборки; отсутствие метки не доказывает отсутствие экземпляров |

Dead-letter означает задание, выведенное из обычного исполнения. User task, receive task и таймер могут штатно ждать без dead-letter. Монитор не вычисляет общий статус «завис». Неизвестная позиция элемента и недоступные данные показываются явно, без ложного нуля.

## Полнота и нагрузка

Снимок собирается несколькими запросами и не транзакционен. Ошибка отдельного раздела сохраняет доступные данные и предупреждение. Ручное/автообновление сохраняет viewport; неактивные мониторы не опрашивают сервер.

Таймаут запроса настраивается для каждого подключения: **5–120 секунд**, по умолчанию **15 секунд**, включая чтение ответа. Автоматических повторов нет. Flowable REST 7.2 считает `total` внутри запроса списка; уменьшение размера страницы не устраняет этот подсчёт. Настройка таймаута позволяет дождаться медленного сервера, но не снижает стоимость SQL. Фильтры по процессу или business key могут сократить выборку.

При обновлении списка прежняя страница остаётся доступной с пометкой о ранее загруженных данных; ошибка обновления не стирает строки. Изменение подключения, его настроек, фильтров или страницы скрывает предыдущий результат. Поздний ответ устаревшего запроса не применяется.

Сводка выбранной версии выполняет **два запроса**, до **100 executions и 100 dead-letter jobs**, с общим таймаутом **8 секунд**. Обхода всех экземпляров и N+1 нет. Связанные ID берутся из этой выборки без дополнительных запросов. Сводка обновляется явно; глобальные фильтры «с экземплярами/ошибками» не предоставляются.

Переменные поддерживают строки, числа, boolean, null и JSON. Бинарные `valueUrl` автоматически не скачиваются; Java-объекты не десериализуются. Локальные переменные execution и stacktrace читаются по запросу.

## Просмотр истории

В каталоге **Экземпляры** выбери **Завершённые экземпляры** или **Все экземпляры из истории**, затем экземпляр из списка либо введи его ID. Фильтры поддерживают ключ процесса, tenant, даты начала/окончания и сортировку. Business key использует точное совпадение. «Все» означает все доступные записи history API, а не гарантию наличия каждого запуска: история могла быть отключена или очищена.

Для экземпляра используется одна схема с историей и текущими позициями runtime. Справа находятся вкладки **Текущее состояние** и **История выполнения** одинаковой ширины. Переключение не перечитывает схему и не сбрасывает масштаб и выбор элемента. Оба источника читаются независимо: недоступность одного не скрывает данные другого. HTTP 404 runtime означает отсутствие экземпляра в текущем API; вкладка объясняет это и предлагает обратиться к сохранённой истории, не объявляя процесс успешно завершённым.

Выбор шага находит элемент на схеме и открывает детали отдельного выполнения. Выбор элемента фильтрует его проходы; кнопка **Показать все шаги** снимает фильтр. Есть поиск по имени, BPMN ID, типу, исполнителю и execution. Стрелки скрыты в журнале по умолчанию, но доступны через **Показывать переходы**; выбор стрелки на схеме также показывает её записи. Каталог слева можно свернуть.

- Схема загружается по `processDefinitionId` исторического экземпляра, а не последней версии процесса. Если deployment недоступен, журнал остаётся доступным; другая версия автоматически не подставляется.
- Синие метки `✓ N` означают записи с зафиксированным окончанием; жёлтые `… N` — наличие записи без окончания. Это не подтверждение успеха, ошибки или текущей активности. Позиции runtime совмещаются с историей на той же схеме и имеют приоритет при выборе зелёного/красного цвета; вкладка подробностей на цвет не влияет.
- Число — количество отдельных записей activity у элемента, включая циклы и multi-instance. При неполной загрузке `≥ N` означает нижнюю границу. У стрелок показывается цвет; отдельные проходы доступны в журнале.
- Журнал упорядочен по времени начала внутри групп; одинаковое время не устанавливает строгий порядок. Группы соответствуют структуре подпроцессов BPMN, не выдуманным связям между параллельными executions или отдельными итерациями scope. Для call activity доступен переход к дочерней истории и возврат назад. Панель связей включает исторические дочерние экземпляры.
- Публичный REST 7.2 не возвращает причину удаления каждого activity. Неоконченный activity не объявляется активным, а оконченный — успешно выполненным. Причина прекращения экземпляра показывается отдельно.
- **Сохранённые переменные** показывают последние исторические значения. Это не значения в момент выбранного шага. Область `task:ID`/`execution:ID` сохраняет привязку локальных переменных; одноимённые переменные разных областей не объединяются. Изменения переменных, требующие более подробной истории, здесь не загружаются; бинарные URL не скачиваются.

Один снимок ограничен **1000 activities, 100 дочерними экземплярами и 100 переменными**. Activities читаются страницами до 100, со стабильной сортировкой по уникальному ID; журнал затем упорядочивается по времени. При превышении лимита это ограниченная выборка, а не гарантированно первые/последние по времени 1000 событий. Отсутствие узла в выборке не доказывает, что он не выполнялся. Перечитывание истории не обходит дочерние процессы и не выполняет N+1-запросов к задачам. После метаданных разделы используют общий бюджет времени, равный таймауту подключения; ошибка раздела сохраняет доступную часть и предупреждение.

Runtime и history обновляются независимо от выбранной вкладки правой панели. Автообновление истории продолжающегося экземпляра выполняется раз в 5 секунд после ответа, только в активной вкладке монитора и видимом окне. Для записи с endTime оно прекращается; ручное обновление доступно. Ошибка обновления метаданных сохраняет прежний снимок с признаком устаревания. Смена экземпляра или настроек исключает применение позднего ответа к другому журналу.

История доступна в объёме, сохранённом движком и разрешённом API. При отсутствии записей или прав интерфейс показывает ограничение; маршрут по соседним выполненным узлам не восстанавливается. При наличии записей `sequenceFlow` подсвечиваются именно эти стрелки. После очистки истории или удаления deployment полную картину восстановить невозможно.

Обычные/timer jobs, retry, воспроизведение по времени и административные действия не включены. Для XML без BPMN DI доступен текст; автоматической раскладки нет. Локальная копия и экспорт BPMN не включают состояние исполнения; SVG/PNG сохраняет видимые совмещённые метки.

### Связанные экземпляры

Родительские и дочерние экземпляры используют одну карточку: роль, название схемы (при отсутствии имени — ключ определения), business key или имя экземпляра и ID. Метаданные родителя читаются отдельно, без загрузки его activities, переменных и схемы. После HTTP 404 в runtime выполняется запрос метаданных history; другие ошибки не маскируются переходом к другому API. Если метаданные недоступны, ссылка по ID остаётся рабочей.

### Общая схема

На одном BPMN ID показывается один маркер и один бейдж. Приоритет: красный dead-letter, зелёная подтверждённая runtime-позиция, затем историческая метка. Отсутствие endTime в history само по себе остаётся оранжевым. Для повторно посещённого текущего элемента `✓ 2 · ● 1` означает два зафиксированных окончания и один текущий execution; `!` обозначает dead-letter jobs. `≥` сохраняет смысл нижней границы исторической выборки. Окончание activity не доказывает успех. Время двух снимков выводится отдельно; данные не транзакционны. При HTTP 404 после завершения runtime-маркеры убираются, история остаётся на схеме.

Бейджи не перехватывают указатель: колёсико и горизонтальные жесты прокручивают холст также при наведении на счётчик. На Linux Shift+колёсико прокручивает по горизонтали, Ctrl+колёсико меняет масштаб. Логотип bpmn.io остаётся видимым рядом с язычком панели и не перекрывает кнопку.

### Сворачивание панелей

Каталог и подробности независимо сворачиваются язычками у нижних краёв панелей. На схеме нет отдельной полосы переключения режимов; кнопки переходов находятся в общем тулбаре монитора. Сворачивание сохраняет масштаб, выбранный элемент и состояние содержимого. Выбор другого элемента не раскрывает правую панель: её язычок один раз мягко подсвечивается и получает небольшую точку до открытия. Обновления по таймеру не вызывают вспышек. При системной настройке уменьшения движения анимация отключена, точка остаётся. Кнопки работают с клавиатуры и сообщают состояние раскрытия.

Легенда и время снимков занимают по одной строке. Пояснения легенды, точные даты снимков и ограничение нетранзакционного чтения доступны в подсказках по наведению или фокусу; Escape закрывает подсказку. Карточки связей используют три строки: `Parent/Child <схема>`, business key/имя, ID.

### Назад и вперёд

Кнопки в верхнем тулбаре монитора проходят по открытым схемам, экземплярам и заданиям. В подсказке доступны название схемы/версия, business key/имя и ID назначения. Обновление данных, выбор элемента и переключение правой вкладки не создают переходов; при возврате правая вкладка восстанавливается. Новый переход после возврата удаляет ветку «вперёд». На каждый монитор приходится своя история до 100 адресов в каждом направлении; она не сохраняется на диск и сбрасывается при смене подключения.

На Linux боковые кнопки мыши используют тот же маршрут через системные команды Electron. Редактор и диалог подключений эти команды не обрабатывают. Детали платформ и проверки — в [ADR 0032](adr/0032-monitor-navigation.md).
