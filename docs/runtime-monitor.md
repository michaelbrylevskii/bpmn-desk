# Просмотр состояния Flowable

«Состояние процессов» читает развёрнутые схемы, запущенные экземпляры, executions, user tasks, переменные и dead-letter jobs. Запуск, завершение, удаление, миграция, retry и deployment не предоставляются.

## Подключения

В «Управлении подключениями» укажи название, REST root и авторизацию: none, Basic или Bearer. Например, стандартный Spring Boot REST root может быть `http://localhost:8080/process-api/`, а отдельное REST-приложение — иметь адрес с `/flowable-rest/service/`. Указывать нужно именно корень API, без Swagger, `/repository`, параметров и реквизитов в URL. Выбор подключения сохраняется между запусками.

Поддержан Flowable REST 7.2. Контракт предусматривает Camunda 7, но его runtime-адаптер пока не реализован. Это не ограничивает локальное редактирование схем Camunda 7. Браузерный preview не подключается к движкам; HTTP-запросы выполняет Electron main через конкретные IPC-операции.

Профили хранятся в `connections.json` в пользовательском каталоге Electron. Пароли и токены сохраняются через защищённое хранилище ОС только по явному выбору пользователя. Если защищённый backend недоступен, включая Linux `basic_text`, секрет живёт в памяти main до закрытия приложения. После перезапуска введи его заново. Пустое поле сохраняет существующий секрет, если адрес и авторизация не изменились; смена адреса или авторизации не переносит старый секрет.

UI получает только признаки наличия и сохранения секрета. Профили и ответы сервера не входят в Git, встроенные примеры или восстановление локальных документов. Повреждённый файл подключений автоматически не перезаписывается. Для удалённого сервера с авторизацией используй HTTPS; проверка сертификатов не отключается, редиректы запрещены. OAuth/SSO обмен, обновление токена, клиентские сертификаты и настройка proxy через UI не включены.

## Каталог и схема

«Процессы» показывает определения с ключом, версией и tenant; поиск работает по имени. Выбор строки открывает конкретную версию XML. Действие «Экземпляры» ограничивает список этим определением; «Все процессы» снимает ограничение.

«Экземпляры» показывает запущенные процессы с фильтром по точному business key. Во всех каталогах доступны tenant-фильтр и страницы по 25 строк. Известный ID экземпляра можно открыть напрямую с верхней панели.

Экземпляр открывает собственный `processDefinitionId`, поэтому публикация новой версии не подменяет схему старого экземпляра. bpmn-js NavigatedViewer не предоставляет палитру моделирования. «Создать локальную копию» открывает отдельный редактируемый документ; значения переменных и состояние экземпляра в BPMN не добавляются.

## Состояние и переменные

Зелёная граница обозначает активный элемент, красная — элемент с dead-letter job. Цифра у активного элемента показывает executions с позицией в узле, без родительских контейнеров; это снимок, а не симуляция токенов. Красный значок показывает число связанных dead-letter jobs. Неизвестные ID элементов отмечаются предупреждением; задание остаётся доступным в списке даже без позиции на схеме.

Нажатие на элемент показывает его ID и выделяет связанные строки executions и задач. Из строки можно перейти к месту на схеме. Для scope-execution без `activityId` показывается parent ID без выдуманной позиции. Доступен переход к родительскому экземпляру вызванного процесса.

«Переменные процесса» показывает имя, тип, область и значение. Поддержаны JSON, строки, числа, boolean и null; поиск фильтрует имена, значения раскрываются по запросу. В executions можно отдельно загрузить локальные и другие переменные выбранного execution. Значения с `valueUrl` обозначаются бинарными и автоматически не скачиваются; Java-объекты не десериализуются.

## Dead-letter jobs

Отдельная вкладка показывает задания с ошибкой независимо от выбранного экземпляра. Фильтры: точный ID экземпляра, tenant и выбранное определение. Строка содержит место ошибки, сообщение и ID экземпляра; выбор открывает его и секцию jobs.

Карточка показывает ID, execution ID, число оставшихся повторов и сообщение. Stacktrace загружается при раскрытии подробностей. Место на схеме определяется через `elementId`, а при его отсутствии — через позицию execution. Задание без ID экземпляра открывается как отдельная карточка.

Dead-letter — признак задания, выведенного из обычного исполнения. User task, receive task, таймер и другие ожидания могут не создавать dead-letter: по одному снимку редактор не объявляет процесс «зависшим». Обычные jobs, timer jobs, история retry и административные действия пока не включены.

## Обновление и границы

Ручное обновление получает новый снимок. Автообновление включается пользователем и выполняется через 5 секунд после завершения предыдущего чтения. Оно приостанавливается при переходе в редактор или скрытии окна. Холст и XML не пересоздаются при каждом снимке; масштаб и выбранный элемент сохраняются.

Снимок собирается несколькими REST-запросами и не является транзакционно согласованным. Быстрые шаги могут пройти между запросами. Недоступный раздел показывается предупреждением; отсутствие прав на jobs не трактуется как отсутствие ошибок. Завершение или удаление экземпляра может дать 404; после ошибки обновления последний снимок помечается устаревшим.

Запрос ограничен 15 секундами, ответ — 16 МБ. Для executions, tasks и dead-letter jobs одного снимка читаются страницы до 5000 записей на раздел, неполная выборка отмечается предупреждением. Для XML без BPMN DI доступен текст; общей автоматической раскладки нет. Завершённые экземпляры, исторические шаги и точный путь по стрелкам не входят в этот этап.

## Проверки

```bash
npm run check
npm run package:linux
npm run test:e2e
npm run test:runtime
```

Последняя команда требует Maven и JDK 17+, поднимает независимый Flowable 7.2/H2, запускает Electron с временными профилями и завершает сервер после тестов. Стенд создаёт настоящие deployments, версии, parallel/multi-instance executions, локальные переменные и dead-letter с сохранённым stacktrace. Java и стенд не включаются в приложение. Обычный E2E без стенда пропускает runtime-проект; CI запускает его отдельным шагом на Linux и Windows.
