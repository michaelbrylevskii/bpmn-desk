# Просмотр состояния Flowable

«Состояние процессов» читает развёрнутые схемы, запущенные экземпляры, executions, user tasks, переменные и dead-letter jobs. Запуск, завершение, удаление, миграция, retry и deployment не предоставляются.

## Вкладки и подключения

На главной странице или в «Новой вкладке» (Ctrl+N) выбери сохранённое подключение и «Открыть монитор». Стартовая страница открывается обычной вкладкой; монитор занимает её место после выбора. Для локального документа есть меню «Создать схему». Пункт «Новое подключение» расположен последним в выпадающем списке. Можно открыть несколько мониторов, в том числе одного сервера: выбранный экземпляр, фильтры, автообновление и положение холста у каждого свои. При переключении к документу тулбар показывает команды редактора, при переключении к монитору — команды чтения состояния.

В «Управлении подключениями» укажи название, REST root и авторизацию: none, Basic или Bearer. Например, стандартный Spring Boot REST root может быть `http://localhost:8080/process-api/`, а отдельное REST-приложение — иметь адрес с `/flowable-rest/service/`. Указывать нужно именно корень API, без Swagger, `/repository`, параметров и реквизитов в URL. Последний выбранный профиль предлагается при создании следующего монитора и сохраняется между запусками. Открытые мониторы, идентификаторы экземпляров и снимки между запусками не восстанавливаются.

«Проверить подключение» использует текущие поля формы и доступно до сохранения, даже без названия профиля. Для существующего профиля пустое поле секрета использует текущий секрет, если адрес, вид авторизации и имя пользователя не менялись. Проверка не изменяет профиль и не сохраняет введённый секрет.

Поддержан Flowable REST 7.2. Контракт предусматривает Camunda 7, но его runtime-адаптер пока не реализован. Это не ограничивает локальное редактирование схем Camunda 7. Браузерный preview не подключается к движкам; HTTP-запросы выполняет Electron main через конкретные IPC-операции.

Профили хранятся в `connections.json` в пользовательском каталоге Electron. Пароли и токены сохраняются через защищённое хранилище ОС только по явному выбору пользователя. Если защищённый backend недоступен, включая Linux `basic_text`, секрет живёт в памяти main до закрытия приложения. После перезапуска введи его заново. Пустое поле сохраняет существующий секрет, если адрес, авторизация и имя пользователя не изменились. Смена этих полей не переносит старый секрет. После сохранения мониторы этого профиля повторяют чтение: смена сервера сбрасывает его контекст, смена пароля сохраняет открытый экземпляр и холст.

UI получает только признаки наличия и сохранения секрета. Профили и ответы сервера не входят в Git, встроенные примеры или восстановление локальных документов. Повреждённый файл подключений автоматически не перезаписывается. Для удалённого сервера с авторизацией используй HTTPS; проверка сертификатов не отключается, редиректы запрещены. OAuth/SSO обмен, обновление токена, клиентские сертификаты и настройка proxy через UI не включены.

## Каталог и схема

«Процессы» показывает определения с ключом, версией и tenant; поиск работает по имени. Выбор строки открывает конкретную версию XML. Действие «Экземпляры» ограничивает список этим определением; «Все процессы» снимает ограничение.

Фильтр «Только последние версии» использует серверный `latest=true`, по умолчанию выключен. Старые версии могут иметь работающие экземпляры и ошибки, поэтому обновление определения не скрывает их автоматически. Повторное нажатие выбранного раздела каталога не сбрасывает его фильтры.

«Экземпляры» показывает запущенные процессы с business key, именем определения, ID и временем старта. Имя определения берётся из ответа списка, без дополнительного запроса на каждую строку; если API его не возвращает, показывается ID определения. Поиск работает по точному business key. Известный ID можно открыть напрямую в этом разделе.

Список не содержит индикатора состояния и подписи Active/Suspended. Состояние приостановки и наличие dead-letter показываются в правой панели после открытия экземпляра. Active означает отсутствие приостановки, а не выполнение прямо сейчас или отсутствие ошибок. Список не запрашивает jobs для каждой строки и не меняет её индикацию после отдельного клика.

В раскрываемых «Фильтрах» доступны tenant, ключ процесса и состояние экземпляра; для dead-letter jobs — execution ID и ID элемента. Сортировка использует поддержанные REST-поля и выбранное направление; размер страницы — 10, 25, 50 или 100. «Применить фильтры» начинает с первой страницы, «Сбросить фильтры» снимает дополнительные ограничения. Прямой переход по ID работает независимо от фильтров списка.

Экземпляр открывает собственный `processDefinitionId`, поэтому публикация новой версии не подменяет схему старого экземпляра. bpmn-js NavigatedViewer не предоставляет палитру моделирования. «Создать локальную копию» открывает отдельный редактируемый документ; значения переменных и состояние экземпляра в BPMN не добавляются.

## Состояние и переменные

При выборе определения холст сначала показывает только его схему. Кнопка «Сводка версии» получает позиции executions и dead-letter выбранного `processDefinitionId`. Это ровно два параллельных запроса, по 100 записей, с общим таймаутом 8 секунд. Просмотр не запускает обход страниц, чтение переменных или запросы к каждому экземпляру. Холст и переходы доступны во время загрузки; ответ от уже оставленной версии или вкладки не применяется.

Бейджи сводки считают разные экземпляры у элемента: multi-instance одного экземпляра считается один раз. Красный бейдж показывает число экземпляров с dead-letter и имеет приоритет над зелёным счётчиком. Зелёный счётчик обозначает наличие executions у элемента, а не исполнение на CPU. При усечении выводится `≥ N` — не менее N экземпляров. Отсутствие метки в неполной выборке не доказывает отсутствие экземпляров или ошибок. Отказ доступа показывается отдельно от пустого ответа; задания без известной позиции обозначаются сообщением. В панели указаны объём выборки и время чтения. Сводку можно скрыть или обновить вручную; автообновление относится только к выбранному экземпляру. Глобальных фильтров списка «с экземплярами»/«с ошибками» нет.

Выбери элемент со сводкой: справа появятся ID связанных экземпляров из уже загруженной выборки. Список объединяет дубликаты и показывает по 10 строк, без дополнительных запросов. Выбор экземпляра открывает его снимок; для строки с dead-letter сразу открывается раздел ошибок. Список выборки не является полным списком экземпляров сервера.

Зелёная граница обозначает активный элемент, красная — элемент с dead-letter job. Цифра у активного элемента показывает executions с позицией в узле, без родительских контейнеров; это снимок, а не симуляция токенов. Красный значок показывает число связанных dead-letter jobs. Неизвестные ID элементов отмечаются предупреждением; задание остаётся доступным в списке даже без позиции на схеме.

Нажатие на элемент выделяет его на холсте, показывает его ID и выделяет связанные строки executions и задач. Повторное нажатие снимает выделение. Из строки можно перейти к месту на схеме. Для scope-execution без `activityId` показывается parent ID без выдуманной позиции. В блоке «Связанные экземпляры» доступны переходы к родителю и дочерним процессам. Список детей запрашивается по parent ID при чтении снимка, с теми же ограничениями полноты и доступа. При выборе любого из них загружается его точное определение.

«Переменные процесса» показывает имя, тип, область и значение. Поддержаны JSON, строки, числа, boolean и null; поиск фильтрует имена, значения раскрываются по запросу. В executions можно отдельно загрузить локальные и другие переменные выбранного execution. Значения с `valueUrl` обозначаются бинарными и автоматически не скачиваются; Java-объекты не десериализуются.

## Экспорт и локальная копия

Общий тулбар позволяет экспортировать открытую runtime-схему в SVG или PNG с белым либо прозрачным фоном. Экспорт включает всю текущую плоскость схемы, цветовые маркеры и бейджи; выделение элемента, рамка фокуса и панели приложения в него не входят. Цвета экспорта не зависят от темы интерфейса. Для раскрытого подпроцесса экспортируется его текущая плоскость, а не объединение всех плоскостей. Метки не добавляются в исходный BPMN.

«Создать локальную копию» открывает документ в новой вкладке и оставляет монитор открытым. Можно вернуться к его состоянию после редактирования.

## Dead-letter jobs

Отдельная вкладка показывает задания с ошибкой независимо от выбранного экземпляра. Фильтры: точный ID экземпляра, tenant, выбранное определение, execution ID и ID элемента. Строка содержит место ошибки, сообщение и ID экземпляра; выбор открывает его и секцию jobs.

Карточка показывает ID, execution ID, число оставшихся повторов и сообщение. Stacktrace загружается при раскрытии подробностей. Место на схеме определяется через `elementId`, а при его отсутствии — через позицию execution. Задание без ID экземпляра открывается как отдельная карточка.

Сообщение «Есть dead-letter jobs: N» в карточке экземпляра открывает раздел ошибок без нового запроса. Оттуда можно перейти к элементу и раскрыть stacktrace. Карточки без доступной позиции не предлагают неработающую ссылку. Недоступные разделы показывают «Состояние недоступно»; счётчик jobs при ошибке загрузки — `—`, а не ноль. Пустые доступные разделы явно обозначают отсутствие результатов.

Dead-letter — признак задания, выведенного из обычного исполнения. User task, receive task, таймер и другие ожидания могут не создавать dead-letter: по одному снимку редактор не объявляет процесс «зависшим». Обычные jobs, timer jobs, история retry и административные действия пока не включены.

## Обновление и границы

Ручное обновление получает новый снимок. Автообновление включается пользователем и выполняется через 5 секунд после завершения предыдущего чтения. Оно приостанавливается при переключении на другую вкладку или скрытии окна. Холст и XML не пересоздаются при каждом снимке; масштаб и выбранный элемент сохраняются.

При изменении размеров окна или панелей сохраняются центр и масштаб холста. Пока ограниченное чтение сводки не завершилось, повторная кнопка недоступна даже после перехода к другой версии; навигация и просмотр схем остаются доступными.

Снимок собирается несколькими REST-запросами и не является транзакционно согласованным. Быстрые шаги могут пройти между запросами. Недоступный раздел показывается предупреждением; отсутствие прав на jobs не трактуется как отсутствие ошибок. Завершение или удаление экземпляра может дать 404; после ошибки обновления последний снимок помечается устаревшим.

Запрос ограничен 15 секундами, ответ — 16 МБ. Для executions, tasks, dead-letter jobs и дочерних экземпляров одного снимка читаются страницы до 5000 записей на раздел, неполная выборка отмечается предупреждением. Для XML без BPMN DI доступен текст; общей автоматической раскладки нет. Завершённые экземпляры, исторические шаги и точный путь по стрелкам не входят в этот этап.

## Проверки

```bash
npm run check
npm run package:linux
npm run test:e2e
npm run test:runtime
```

Последняя команда требует Maven и JDK 17+, поднимает независимый Flowable 7.2/H2, запускает Electron с временными профилями и завершает сервер после тестов. Стенд создаёт настоящие deployments, версии, parallel/multi-instance executions, локальные переменные и dead-letter с сохранённым stacktrace. Java и стенд не включаются в приложение. Обычный E2E без стенда пропускает runtime-проект; CI запускает его отдельным шагом на Linux и Windows.
