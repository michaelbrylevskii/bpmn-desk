# Сборки и проверка Windows

Версия приложения: 0.2.0. Целевая система: Windows 10/11 x64. EXE собираются нативно в GitHub Actions и локально на Linux через Docker. Автоматические проверки запуска, UI, сохранения и настроек на Windows Server 2022 прошли; установка, удаление и файловые ассоциации на Windows 10/11 ещё не проверены.

## Готовые файлы

Релизные файлы доступны на [GitHub Releases](https://github.com/michaelbrylevskii/bpmn-desk/releases); их контрольные суммы находятся в SHA256SUMS самого релиза. Размеры и суммы ниже относятся к последней локальной сборке в `release/` и могут отличаться от сборок CI из-за временных меток упаковки.

| Файл в `release/` | Использование | Размер |
| --- | --- | --- |
| `BPMN-Desk-0.2.0-x64-Setup.exe` | Установка для текущего пользователя; выбор каталога и English/Русский | 115 864 416 байт |
| `BPMN-Desk-0.2.0-x64-Portable.exe` | Запуск без установки | 115 701 408 байт |

Portable распаковывает приложение во временный каталог. Настройки языка, масштаба и восстановление сохраняются в обычном пользовательском профиле Electron, а не рядом с EXE. Для запуска не нужны Node.js, npm или Java. Артефакты не подписаны сертификатом издателя; Windows может показать предупреждение о неизвестном издателе.

Открытие конкретной схемы через PowerShell:

```powershell
& '.\BPMN-Desk-0.2.0-x64-Portable.exe' 'C:\Схемы процессов\Документ.bpmn20.xml'
```

Установщик добавляет ассоциацию `.bpmn`. Для `.bpmn20.xml`/`.xml` используй Open / Открыть, drag-and-drop или CLI. Язык установки выбирается отдельно; приложение с новым профилем запускается на английском и переключается через Language / Язык.

## Сборка на Windows

Рекомендуется Node.js 24 и npm; точный диапазон указан в `package.json`. В каталоге репозитория:

```powershell
npm ci
npm run setup:electron
npm run check
npm run package:windows
```

Команда создаёт оба EXE и каталог `release/win-unpacked/`. Архитектура x64 указана явно. electron-builder скачивает сборочные инструменты в `.cache/`; автоматической публикации нет.

## Кросс-сборка на Linux

Если Wine уже установлен, используй `npm run package:windows`. Без Wine нужен работающий Docker:

```bash
npm ci
npm run setup:electron
npm run package:windows:docker
```

Команда собирает JS/иконку на хосте и упаковывает EXE в `electronuserland/builder:24-wine`. Digest образа закреплён в `scripts/package-windows-docker.mjs`. Контейнер получает только каталог проекта, использует UID/GID разработчика и удаляется после сборки. `node_modules` должен быть установлен на Linux-хосте; каталог зависимостей, скопированный с Windows, не подходит. Кеш инструментов и профиль Wine остаются в `.cache/`, которую dev-сервер не обходит.

Docker daemon должен видеть каталог репозитория для bind mount. В Docker Desktop проверь общий доступ к этому каталогу. В диске Docker должно хватать места на образ и упаковку; очистка неиспользуемых ресурсов выполняется отдельно от сборки, автоматически ничего не удаляется.

## Автоматическая проверка на Windows

После `package:windows`:

```powershell
npm run test:e2e -- --project=windows
```

Тест запускает `release/win-unpacked/BPMN Desk.exe`, передаёт копию схемы по пути с кириллицей и пробелами, проверяет packaged runtime, sandbox/preload, отображение демонстрационной схемы Flowable, английский default, XML-поиск, переключение языка, изменение/сохранение Flowable-свойства и bundled examples. Используется отдельный временный профиль и копия схемы; исходные файлы не меняются. Скриншот: `test-results/windows-editor.png`. На Linux тест пропускается.

Для проверки уже установленного приложения можно указать путь:

```powershell
$env:BPMN_DESK_WINDOWS_EXECUTABLE = 'C:\путь\к\установленному\BPMN Desk.exe'
npm run test:e2e -- --project=windows
Remove-Item Env:BPMN_DESK_WINDOWS_EXECUTABLE
```

Переменная предназначена для настоящего executable приложения, а не для installer/portable launcher: последние запускают дочерний процесс и требуют отдельной ручной проверки.

## Ручная приёмка на Windows

Эти пункты пока **не выполнены**:

- [ ] Запустить portable обычным пользователем; открыть встроенный пример и копию своей схемы.
- [ ] Проверить светлую/тёмную тему, Ctrl+/Ctrl−/Ctrl0, EN/RU, поиск XML и переход к выбранному элементу.
- [ ] Изменить Flowable-свойство и дополнительный атрибут, проверить undo/redo; сохранить копию в каталог с кириллицей и пробелами, переоткрыть её и экспортировать SVG.
- [ ] Закрыть и снова открыть portable: язык/масштаб сохраняются, несохранённая схема доступна для восстановления.
- [ ] Установить NSIS-сборку для текущего пользователя, выбрать каталог; проверить запуск через ярлыки и иконку.
- [ ] Открыть копию `.bpmn` из Проводника и второй файл при уже открытом редакторе: оба документа должны оказаться в одном окне.
- [ ] Удалить установленное приложение через Windows, затем проверить повторную установку.

## Проверка состава на Linux

Выполнены `7z t` обоих EXE и вложенных `$PLUGINSDIR/app-64.7z`. Payload обоих форматов идентичен; извлечённые EXE, `app.asar`, PNG и все примеры побайтово совпадают с `win-unpacked`/источниками. ASAR содержит main/preload/renderer, Windows runtime имеет PE x64 и собственные ресурсы иконки/версии. Проверка архивов не заменяет запуск Windows.

SHA-256 готовых файлов:

```text
91ae2ea290b0449ec248118ea6fc11f6b87481c6104f149163c78f26bca3d82d  BPMN-Desk-0.2.0-x64-Setup.exe
7efc20c0504bf73f56db7b32c7d7306ff975a188bf9cda00dbc206ada2828fca  BPMN-Desk-0.2.0-x64-Portable.exe
```

На Windows их можно сравнить через `Get-FileHash <путь-к-EXE> -Algorithm SHA256`. Пересборка может изменить суммы из-за временных меток упаковки.

Решения и альтернативы: [ADR 0009](adr/0009-windows-distribution.md). Способ сборки согласован с [документацией electron-builder](https://www.electron.build/v26/docs/features/multi-platform-build/); содержание и состояние проверки описывают текущие локальные артефакты.
