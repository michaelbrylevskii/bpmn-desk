## MON-09–MON-14: реализация следующей итерации

Код: `9491b0b` (общий контекст), `4abcc55` (устойчивое ожидание wheel в тесте), `f012c31` (сводка, история и панель). Реализованы [ADR 0036](adr/0036-shared-definition-context.md) и [ADR 0037](adr/0037-global-summary-and-history.md). Изменения локальные, версия сохранена 0.6.0.

Проверены общий фиолетовый чип и снятие/сброс во всех каталогах, сохранение независимых локальных условий, сброс страниц; общий переключатель сводки, миграция старого `false`, приоритет сохранённого значения, работа во время загрузки и сохранение после полного перезапуска Electron. Ошибка истории не скрывает runtime. Исторические повторы считаются по разным экземплярам, источник открывает соответствующую правую вкладку. Проверены постоянная ширина панели, плейсхолдер, язычок, единый порядок полей и ссылка на точную версию. Снимки общего контекста проверены в светлой и тёмной темах; история сводки проверена на двух языках.

`npm run check`: strict TypeScript, ESLint и **121 unit-тест в 31 файле** — успешно. `npm run package:linux`: AppImage x86_64 собрана. **`npm run test:e2e`: 103 passed, 19 ожидаемых skip (5,8 минуты)**, включая обе проверки готовой AppImage. Пропуски — Windows и 18 сценариев отдельного Flowable-стенда, выполненных ниже.

Независимый Flowable: первоначальный прогон дал 17 passed и один неверный тестовый прогноз — наличие historic activity на позиции dead-letter. На стенде неудачная async-транзакция не оставила такую запись. Уточнены ожидаемые данные и добавлена проверка пустой исторической выборки при существующем dead-letter; повтор обоих сценариев `runtime-summary.spec.ts` — **2 passed**. Таким образом все 18 разных сценариев Flowable успешно выполнены. Проверены три ограниченных GET и сортировка истории, дедупликация multi-instance, экспорт, частичный отказ 403, общий deadline 5 секунд включая медленное тело и очередь при смене определения. Unit-тесты отдельно проверяют конфигурацию бюджета 5 и 120 секунд.

Непостоянный сбой wheel из предыдущего планирования учтён: тест удерживает Ctrl/Shift до обработки wheel и проверенного изменения transform, а не отпускает сразу после отправки события. Производственная логика жестов не менялась. Целевой повтор — 2 passed; обе проверки колёсика и слоёв холста также прошли в полном прогоне.

Для ручной проверки пользователя: снять общий чип из любого каталога; переключить сводку и перезапустить приложение; выбрать элемент определения и переключить Runtime/History; сбросить выбор кликом по фону и свернуть язычок; сравнить сведения экземпляра и перейти по ID определения. Запуск: `npm run dev` либо `release/BPMN-Desk-0.6.0-x86_64.AppImage`. Push/релиз не выполнялись. Windows/macOS не проверялись.

Проверяемый код: `68fcbcc` и `5674429`; следующий коммит меняет только документацию.

19 пропусков общего E2E — один Windows target и 18 сценариев отдельного Flowable-стенда. Все 18 выполнены успешно отдельной командой ниже. Первый общий прогон выявил старое ожидаемое название правой вкладки в AppImage-тесте; проверка обновлена, заключительный полный прогон завершился без ошибок.

Команда проверки реального движка:

```sh
npm run test:runtime -- tests/e2e/runtime.spec.ts tests/e2e/runtime-history.spec.ts tests/e2e/runtime-summary.spec.ts tests/e2e/runtime-search.spec.ts tests/e2e/runtime-ui.spec.ts
```

Она запускает независимый Flowable с оригинальными тестовыми схемами проекта; пользовательские схемы и подключения не используются. Проверены точные версии определений, текущие и исторические экземпляры, AND-фильтры API, пагинация, multi-instance, переменные, dead-letter, авторизация, сводка и переходы между родителем/детьми.

E2E отдельно проверяют:

- Закрытые фильтры без поисковых форм над списком, сочетание нескольких условий, индивидуальное снятие предфильтра версии, независимые условия runtime/history и сброс к последним версиям.
- Начальную правую вкладку при выборе строки runtime/history; обе локализации и темы в узком окне.
- Единую прокрутку всей правой панели с 30 записями журнала при высоте окна 600 px, отсутствие скролла у вложенных сведений и списка.
- Отображение схемы и открытие XML во время задержанного на 3 секунды ответа сводки; легенда не дублируется в подсказке статистики.
- Сохранение DOM меток, выбора, масштаба, страницы и прокрутки подробностей при обновлении; ошибки обновления сохраняют ранее загруженные данные с явным статусом.
- Независимое раскрытие нескольких записей истории, фильтрацию только по выбору на схеме, XML с подсветкой и поиском только для чтения, тонкую сплошную рамку выбора.

Локальный артефакт: `release/BPMN-Desk-0.6.0-x86_64.AppImage`; номер версии сохранён до отдельного решения о релизе.

## Ручная проверка пользователя

Ожидается после передачи локальной сборки. Запуск из исходников: `npm run dev`.

- На обеих локализациях пройти четыре каталога, раскрыть фильтры, сочетать условия, свернуть форму, снять отдельные чипы и сбросить условия.
- Из определения перейти к экземплярам его версии; снять чип версии. Переключить runtime/history и убедиться, что их условия независимы; проверить начальную правую вкладку и ручное переключение.
- Уменьшить высоту окна, открыть процесс с длинным бизнес-ключом и связанными процессами. Прокрутить всю правую панель до журнала, раскрыть несколько записей без исчезновения соседей.
- Проверить сводку: автозагрузка, состояние в подсказке без повторной легенды, скрытие/показ меток, общее обновление. При медленном API схема должна появляться независимо от сводки.
- С включённым авторефрешем выбрать элемент и прокрутить подробности; проверить сохранение выбора, раскрытия, страницы и прокрутки. Сравнить выделение элементов с редактором в обеих темах.
- Проверить назад/вперёд, сворачивание панелей, жесты колёсика над метками и XML-поиск.

Windows/macOS в рамках этой доработки не проверялись.
