## Бейджи у соседних граничных событий

2026-10-30: `4a29acf` реализует [ADR 0040](adr/0040-monitor-badge-placement.md). Бейджи автоматически расходятся с зазором, учитывают фигуры, подписи, соседние метки и линии привязки. Координаты и линии сохраняются в SVG/PNG; команда вписывания учитывает вынесенные метки. Обновление без новых данных сохраняет DOM и атрибуты; рост счётчика пересчитывает ширины и позиции без изменения BPMN.

`npm run check` — strict TypeScript, ESLint, **126 unit-тестов в 32 файлах**, успешно. Целевой Electron-прогон — **10 passed**: задача с двумя соприкасающимися boundary events, отсутствие пересечения реальных прямоугольников, обе темы, рост счётчиков, сохранение DOM, совпадение координат SVG с холстом, SVG/PNG с тремя секциями, жесты колёсика и обновление сводки. Снимки плотной схемы в обеих темах просмотрены визуально.

Первый целевой прогон выявил гонку теста wheel: команда наведения завершалась до обработки mouseover в renderer, а ZoomScroll подключает wheel после этого события. `187fc2b` ждёт реального hover SVG; отдельный повтор — 2 passed, затем оба сценария прошли в целевом наборе. Приложение не перехватывает жесты метками.

Независимый Flowable (`runtime-ui.spec.ts`, `runtime-summary.spec.ts`) — **6 passed** после повторного запуска. Первый запуск дал 4 passed и два сбоя: устаревшее ожидание CSS `inline-flex` вместо вычисленного `flex` у flex-item нового контейнера и HTTP 500 стенда на ошибочный путь `/process-api/и/repository/process-definitions`. Ожидание центрирования обновлено; в повторе все шесть сценариев, включая подключение и экспорт, прошли успешно. Причина появления лишнего сегмента пути в первом запуске не установлена, сетевой код приложения не менялся.

`npm run package:linux` — успешно, AppImage x86_64 собрана: `release/BPMN-Desk-0.6.0-x86_64.AppImage`. Полный `npm run test:e2e` — **107 passed, 19 ожидаемых skip (4,1 минуты)**, включая обе проверки готовой AppImage, новую плотную схему, экспорт и жесты. Пропуски — Windows и сценарии отдельного Flowable-стенда; затронутые сценарии Flowable выполнены отдельным прогоном выше.

Для ручной проверки: открыть плотную схему с соседними граничными событиями; проверить принадлежность меток по линиям, несколько масштабов, колёсико над бейджем и SVG/PNG. Изменения локальные, без push и релиза; версия сохраняется 0.6.0. Windows/macOS не проверялись.

## Приоритет схемы и обозначение N+

2026-10-30: `9847d13` заменяет `≥17` на `17+` в сводке, истории экземпляра, числе проходов и экспорте; смысл — не менее 17 — сохраняется. `f5e73da` запускает сводку после отображения выбранной схемы либо XML fallback; старый сигнал готовности не разрешает загрузку новой версии. Ручная проверка: при медленном API открыть определение и убедиться, что схема появляется раньше статистики; быстро перейти на другое определение; проверить `N+` и пояснение «не менее N» в подсказке. ## Ручная проверка пользователя

Ожидается после передачи локальной сборки. Запуск из исходников: `npm run dev`.

- На обеих локализациях пройти четыре каталога, раскрыть фильтры, сочетать условия, свернуть форму, снять отдельные чипы и сбросить условия.
- Из определения перейти к экземплярам его версии; снять чип версии. Переключить runtime/history и убедиться, что их условия независимы; проверить начальную правую вкладку и ручное переключение.
- Уменьшить высоту окна, открыть процесс с длинным бизнес-ключом и связанными процессами. Прокрутить всю правую панель до журнала, раскрыть несколько записей без исчезновения соседей.
- Проверить сводку: автозагрузка, состояние в подсказке без повторной легенды, скрытие/показ меток, общее обновление. При медленном API схема должна появляться независимо от сводки.
- С включённым авторефрешем выбрать элемент и прокрутить подробности; проверить сохранение выбора, раскрытия, страницы и прокрутки. Сравнить выделение элементов с редактором в обеих темах.
- Проверить назад/вперёд, сворачивание панелей, жесты колёсика над метками и XML-поиск.

Windows/macOS в рамках этой доработки не проверялись.
