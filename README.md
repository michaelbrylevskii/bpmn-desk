# BPMN Desk

Локальный просмотрщик и редактор BPMN 2.0 с поддержкой расширений Flowable и Camunda 7. Без учётной записи, сервера и загрузки схем в облако.

Версия 0.3.0 добавляет Camunda 7, экспорт PNG и системную тему. [Изменения версии](docs/releases/0.3.0.md) · [Поддержка Camunda 7 и её границы](docs/camunda7.md).

Стек: Electron, React, TypeScript, bpmn-js. Сборки: Linux AppImage и Windows x64 (установщик и portable). Основная платформа — Linux. Версия 0.3.0 прошла нативные проверки обеих платформ в GitHub Actions; результаты — в [отчёте проверки](docs/validation.md).

## Запуск Linux AppImage

Готовые файлы доступны на [странице релизов](https://github.com/michaelbrylevskii/bpmn-desk/releases). После локальной сборки файл находится в `release/BPMN-Desk-0.3.0-x86_64.AppImage`.

```bash
chmod +x release/BPMN-Desk-0.3.0-x86_64.AppImage
./release/BPMN-Desk-0.3.0-x86_64.AppImage
# Сразу открыть схему:
./release/BPMN-Desk-0.3.0-x86_64.AppImage /путь/к/процессу.bpmn20.xml
```

Если в системе недоступен FUSE, первый аргумент должен быть `--appimage-extract-and-run`:

```bash
./release/BPMN-Desk-0.3.0-x86_64.AppImage --appimage-extract-and-run
```

Также можно выполнить `--appimage-extract` и запустить `squashfs-root/AppRun`. В этой проверочной среде нет `/dev/fuse`; содержимое AppImage проверено после извлечения, с включённым Chromium sandbox. Менять системные настройки или отключать sandbox для приложения не требуется.

## Запуск Windows

После сборки Windows в `release/` доступны два варианта версии 0.3.0:

- `BPMN-Desk-0.3.0-x64-Setup.exe` — установщик для текущего пользователя с выбором каталога и языка установки.
- `BPMN-Desk-0.3.0-x64-Portable.exe` — запуск без установки.

Обе сборки содержат редактор и примеры; Node.js и Java для запуска не нужны. Portable хранит настройки в обычном пользовательском профиле Electron. Сборки не подписаны сертификатом издателя. CI проверяет запуск готового EXE на Windows Server 2022. Ручная работа инсталлятора подтверждена пользователем для 0.2.0; результаты новой версии фиксируются отдельно. [Сборка и проверка Windows](docs/windows.md).

## Разработка

Рекомендуется Node.js 24 и npm. Поддерживаемые диапазоны инструментов: Node.js `^22.12.0 || ^24.0.0 || >=26.0.0`, закреплены в `package.json`. Java требуется только для дополнительных проверок Flowable и Camunda 7.

```bash
npm ci
npm run setup:electron
npm run dev
```

`npm run dev:web` запускает браузерный preview на `http://127.0.0.1:5173`. В нём сохранение скачивает файл; обычное сохранение по пути и недавние документы доступны в desktop-приложении.

## Возможности

- Вкладки, открытие и drag-and-drop BPMN/XML, недавние файлы, CLI и передача файла существующему окну.
- Палитра BPMN: элементы, связи, события, шлюзы, пулы, subprocess и стандартные операции bpmn-js.
- Поиск по имени/ID, масштаб схемы и всего интерфейса, независимый undo/redo документов, экспорт SVG и PNG с белым или прозрачным фоном.
- Общие BPMN-свойства с индикацией заданных значений/умолчаний, условия, таймеры, ссылки на сообщения/ошибки/сигналы; редактирование их определений.
- Flowable: реализации задач, исполнители, async/exclusive, retry, listeners, поля, formProperty, in/out.
- Camunda 7: external tasks, async, listeners, параметры map/list/script, formData, connectors, in/out, DMN/call bindings, события и multi-instance; автоматическое определение профиля по URI.
- Дополнительные namespaced атрибуты и произвольные extensionElements, включая метаданные Flowable Design и пользовательские namespaces.
- XML-режим с поиском, заменой и переходом к выбранному элементу; явное применение правок.
- Английский интерфейс по умолчанию и переключение English/Русский с сохранением выбора.
- Системная/светлая/тёмная тема интерфейса и холста, диагностика и отменяемое исправление размещения граничных событий, восстановление несохранённой работы.
- Атомарная запись файла и обнаружение внешних изменений перед обычным сохранением.

## Как редактировать

Новый профиль запускается на английском. В меню Language / Язык выбери English или Русский; EN/RU также доступен в toolbar. Выбор сохраняется между запусками, применяется сразу и не меняет XML, имена элементов или открытых файлов.

Открой схему и выбери элемент на холсте или в списке слева. Значения форм применяются при потере фокуса. Удобные формы Flowable и Camunda 7 используют те же данные, которые видны в разделе дополнительных атрибутов. Для нового атрибута укажи `prefix:name`, значение и URI namespace. Пустое значение удаляет атрибут.

Кнопка новой схемы, новая вкладка, Ctrl+N и native меню открывают выбор Flowable, Camunda 7 или BPMN 2.0. Escape отменяет создание. Открытые схемы определяются автоматически. Зелёная точка обозначает Flowable, оранжевая — Camunda 7; цвет не является статусом валидации. При использовании обоих namespace отображаются обе группы и предупреждение. Конвертация между движками не выполняется.

Заданные значения выделены акцентной боковой гранью поля. Стандартные BPMN-умолчания берутся из descriptor; для Flowable умолчания движка не угадываются. Явное стандартное значение, совпадающее с умолчанием, может быть опущено каноническим экспортом moddle и при переоткрытии показано как умолчание.

Масштаб интерфейса: меню «Вид», Ctrl+ (или Ctrl=), Ctrl−, Ctrl0. CtrlShift0 вписывает диаграмму; кнопки на холсте меняют только масштаб схемы. Настройки темы и масштаба не меняют BPMN. Явные цвета DI сохраняются; SVG экспортируется в светлой палитре для просмотра и печати.

В панели XML нажми Search / Поиск или CtrlF. В строке доступны поиск, стрелки перехода, число совпадений, регистр, regex и целые слова. Кнопка раскрытия показывает отдельную строку замены. Выбор элемента на схеме или в списке прокручивает XML и подсвечивает границы его тега; кнопка перехода повторяет прокрутку. Если ID отсутствует в черновике, это показано рядом с поиском.

Кнопка Search / Поиск также закрывает панель; запрос сохраняется. CtrlF открывает или фокусирует поиск, Escape закрывает его.

Три кнопки темы справа: монитор следует системной теме, солнце задаёт светлую, луна — тёмную. Выбор сохраняется; системный режим реагирует на смену темы ОС без перезапуска. Новый профиль использует системный режим, прежний ручной выбор светлой/тёмной темы остаётся в силе.

Кнопка экспорта повторяет выбранный вариант. Стрелка рядом открывает SVG, PNG с белым фоном и PNG с прозрачностью. PNG строится из всей схемы, без интерфейса, в масштабе 2× светлой экспортной палитры; явные DI-цвета сохраняются. Экспорт не сохраняет изменения BPMN и не добавляет изображения в недавние схемы.

Если граничные события закрывают маркер подпроцесса или друг друга, в свойствах и диагностике доступно «Разнести события». Размещение меняется только после нажатия; CtrlZ отменяет весь набор перемещений. Это локальное исправление, общая автоматическая раскладка не предусмотрена.

Для сложных и проектных расширений открой «XML расширений» и нажми «Применить расширения»; изменение блока отменяется обычным undo. Для всей схемы используй нижнюю вкладку XML. Правки полного XML нужно применить или отменить перед сохранением; его применение начинает новую историю команд. Ошибочный импорт сохраняет текущую диаграмму, но при восстановлении после ошибки визуального импорта история команд может сброситься.

Отдельный XML-блок расширений выровнен от левого края с двумя пробелами на уровень. Содержимое строк, скриптов, CDATA и блоков со значимыми пробелами сохраняется; открытие панели не изменяет схему.

Ошибка применения XML показывает, что изменения отклонены, и предлагает исправить XML. Вывод парсера раскрывается в «Технических подробностях». Уведомления закрываются автоматически: успех через 5 секунд, ошибка через 12. Наведение, фокус и открытые подробности приостанавливают закрытие; после окончания взаимодействия действует задержка 1,5 секунды.

При внешнем изменении файла редактор остановит обычное сохранение. Переоткрой файл или выбери «Сохранить как». После восстановления предыдущей сессии используй «Сохранить как»: восстановленные документы не получают прежние файловые разрешения.

## Проверки и сборка

```bash
npm run check                    # strict TypeScript, ESLint, unit/roundtrip
npm run setup:e2e                # установить тестовый Chromium
npm run package:linux            # собрать AppImage
npm run test:e2e                 # UI, Electron, CLI, native save, AppImage
npm run validate:flowable        # дополнительно: JDK 17+, Maven
npm run validate:camunda         # Model API Camunda 7.24, экспорты UI и изменённая модель
npm run package:windows          # Windows x64: NSIS + portable; Windows или Linux с Wine
npm run package:windows:docker   # Linux: те же EXE через Docker с Wine
npm run capture:screenshots     # обновить три preview на встроенной демонстрационной схеме
```

Flowable-проверка использует экспорты встроенных схем, полученные UI-тестами в `.cache/flowable-exports/`. Она сравнивает исполняемые модели через официальный конвертер Flowable 7.2: пять исходных экспортов и отдельный экспорт после исправления размещения из `.cache/flowable-layout/`. Camunda-проверка отдельно использует два примера, изменённый integration и результат copy/paste; [подробности](docs/camunda7.md). Java не входит в приложение. AppImage-тест пропускается до сборки артефакта и на других ОС.

GitHub Actions выполняет проверки и нативные сборки на Linux и Windows. После успешного прогона тег `v<версия>` публикует релиз с тремя дистрибутивами и SHA256SUMS. Пользовательские пакеты в CI не подключаются. Процесс: [publication.md](docs/publication.md).

## Ограничения

- Linux x86_64 проверен локально и в CI. Windows x64 installer/portable собраны в CI, запуск готового приложения и UI проверены на Windows Server 2022. Ручная установка и ассоциации требуют отдельной приёмки; пользовательское подтверждение инсталлятора относится к 0.2.0. macOS — будущая платформа.
- Требуется BPMN DI с координатами. Для XML без DI доступен исходник, автоматической раскладки пока нет.
- Файлы должны иметь кодировку UTF-8; UTF-8 BOM поддерживается, неверные байты отклоняются.
- Неизвестные namespaces сохраняются, но XML-конструкции, которые moddle не может сохранить, блокируют импорт/сохранение. В частности, произвольный mixed content не обещается.
- Namespaced кастомные атрибуты поддержаны; неизвестные неименованные BPMN-атрибуты могут блокировать импорт.
- XML может менять форматирование, префиксы и CDATA. Побайтовое сохранение исходника не обещается.
- PNG ограничен стороной 16 384 px, площадью 32 млн пикселей и файлом 20 МБ. Для более крупных схем используй SVG.
- Редактор не запускает процессы, expressions, scripts и Java delegates, не делает deployment и не заменяет runtime-валидацию Flowable/Camunda.
- Восстановление ограничено объёмом localStorage; ошибки показываются. При закрытии окна сфокусированное поле применяется и состояние записывается перед подтверждением.
- DMN/CMMN, совместное редактирование, синхронизация Git и облако не включены.

Результаты версии 0.3.0: [validation.md](docs/validation.md). Исторический отчёт 0.2.0: [validation-0.2.0.md](docs/validation-0.2.0.md). Дополнительные пользовательские наборы: [local-schema-packs.md](docs/local-schema-packs.md).
